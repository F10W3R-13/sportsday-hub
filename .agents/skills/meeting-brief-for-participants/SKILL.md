# Skill: meeting-brief-for-participants

# 회의 참가자용 브리프 작성 — 스포츠데이 기획 프로젝트

회의 진행자가 설계한 회의 절차(안건서·안내문·마스터지침)를 바탕으로, **각 팀(참가자) 관점의 사전 공유 브리프**를 자동 생성한다.

## 핵심 원칙 — 참가자는 엔드포인트만 필요하다

이 스킬의 존재 이유는 **"진행자의 시야"와 "참가자의 시야"를 분리하는 것**이다.

- ❌ **진행자의 시야**(안건서·안내문에 섞여 있는 것): 회의 설계 의도, "왜 이 항목을 🟡로 뒀는가", 의존관계 매핑, 25-2와의 비교, 보전 한도 이월 사정, 리드타임 판단 배경 — 참가자는 알 필요 없다.
- ✅ **참가자의 시야**(브리프에 있어야 할 것): **자기가 뭘 준비하고, 뭘 발표하고, 뭘 해야 하는지 + 왜 그래야 하는지(자기 업무 이유만)**.

**브리프에는 진행자의 메타적 고민이 단 한 줄도 들어가면 안 된다.** 참가자는 설계 이유가 궁금한 게 아니라 "내가 뭘 하면 되는지"가 궁금하다.

## 언제 사용하는가

아래 상황에서 트리거한다:

- 회의 자료(안건서·안내문·마일스톤)가 갖춰진 뒤, 회의 3~4일 전
- 진행자가 "각 팀 톡방에 공유할 자료 만들어줘", "팀별로 뭐 해야 하는지 정리해줘", "참가자용 브리프 작성" 등을 요청할 때
- 각 팀 폴더에 `2차 회의 사전 공유 (팀명용).md` 형태의 파일을 생성할 때

## 사전 입력 — 이것들을 먼저 파악한다

브리프를 쓰기 전, 아래 문서들을 읽어 회의의 "엔드포인트"를 추출한다:

1. **안건서(진행용)** — 각 팀 슬롯의 "오늘 모을 것 / 오늘 안 함" + 발표 시간 + Action Item
2. **안내문** — 각 팀 사전 준비 요청 항목
3. **마스터지침 4-2** — 마일스톤/산출물 일정
4. **각 팀 지침** — 해당 팀의 산출물·연계

핵심은 이 문서들에서 **참가자에게 필요한 정보만 골라내는 것**이다. 설계 배경은 버린다.

## 브리프 구조 (4단 고정)

각 팀 브리프는 **반드시 아래 4단 구조**를 따른다. 순서와 제목을 바꾸지 않는다.

```
# {팀 이모지} {팀명} — {회의명} 사전 공유

> 회의: {일시} / {발표 시간}
> 발표 담당 1명을 정해서 오세요.

---

## ✅ 회의 전까지 할 것 (8/9 회의 시작 전)

### 1. {준비 항목}
- {구체적 행동}
- **왜**: {자기 업무 관점에서의 이유 — 진행자 설계 이유 X}
- **주의**: {회의에서 안 다루는 것 있으면 명시}

### 2. ... (항목별 반복)

### N. 발표 담당 1명 지정
- {발표 시간}

---

## 🎤 회의에서 발표할 것
- {발표 내용}
- **"확정"이 아니라 "이 방향으로 가려는데 다들 괜찮은지" 확인하는 자리입니다.**
- {회의에서 다루지 않는 것 명시}

---

## 📋 회의 후 할 것
- {기한별 산출물 — 마스터지침 4-2에서 해당 팀 것만}
- 중요 기한에는 **볼드/⭐**

---

## 💡 배경 — 왜 이 업무들을 해야 하나
- {각 준비 항목별 이유 — 자기 업무 관점만}
```

## 작성 규칙 (핵심)

### 1. "왜"는 자기 업무 관점에서만
- ✅ 좋은 예: "게임이 정해져야 타임라인팀이 시간표를 그릴 수 있고, 예산팀이 물품 리스트를 만들 수 있습니다"
- ❌ 나쁜 예: "입장료는 보전 한도 파악 전이므로 ⚪로 이월하고, 단체티는 리드타임 따라 결정 시점 유연하게..." (진행자 설계)

### 2. 진행자 메타 용어를 그대로 가져오지 않는다
- ❌ "🟡 방향 논의", "⚪ 보류", "보전 한도 이월", "크리티컬 패스", "25-2와의 차이"
- ✅ "오늘 안 다룹니다, 8/16에 하세요", "입장료는 이 회의에서 안 다룹니다"

### 3. 발표 시간·기한 등 **구체적 숫자**는 그대로
- 발표 담당 지정, 발표 시간(8분+Q&A 12분), 회의 후 산출물 기한(8/16, 8/20, 8/13 등)은 참가자에게 필요한 하드 정보이므로 정확히.

### 4. 각 팀은 자기 팀 것만
- 다른 팀의 업무·의존관계는 참가자가 몰라도 된다. "타임라인팀에 게임 방향 전달"처럼 **해당 팀이 직접 하는 인계**만 포함.

### 5. 파일은 각 팀 폴더에, 파일명 양식 통일
- `{팀 폴더}/2차 회의 사전 공유 ({팀명}용).md`
- 회의 차수가 바뀌면 "2차"를 "3차"로 바꾼다.

## 팀 구성 (이 프로젝트 고정)

| 팀 | 폴더 | 이모지(예시) |
|---|---|---|
| 컨텐츠팀 | `컨텐츠팀/` | 🎮 |
| 예산팀 | `예산팀/` | 💰 |
| 교환담당팀 | `교환담당팀/` | 🌐 |
| 타임라인/인원관리팀 | `타임라인_인원관리팀/` | ⏰ |

팀 구성이 바뀌면 안건서·마스터지침을 보고 팀 수를 맞춘다.

## 절차

1. 안건서·안내문·마스터지침 4-2·각 팀 지침을 읽는다.
2. 각 팀별로 "회의 전 / 회의에서 / 회의 후 / 배경" 엔드포인트를 추출한다.
3. 위 4단 구조로 각 팀 브리프를 작성한다.
4. 각 팀 폴더에 파일을 저장한다.
5. 진행자에게 "각 팀 톡방에 복붙하시면 됩니다"로 보고한다.

## 주의 — 이 스킬의 빈틈 (프로젝트 종반에 보완 예정)

이 스킬은 8/9 2차 회의 1회 적용에서 도출되었다. 아래 상황은 아직 검증되지 않았다:

- **방중회의(8/21)** 같은 비정기 회의에 적용할 때 구조가 맞는지
- **팀 구성이 바뀌는 경우** (다음 학기 등)
- **회의 차수가 3차 이상** 갈 때 마일스톤 업데이트 흐름
- **참가자가 "왜"에 대해 추가 질문**을 하는 경우 — 브리프가 부실한지 신호

프로젝트가 끝날 때쯤 이 빈틈들을 점검해 스킬을 강화한다.
