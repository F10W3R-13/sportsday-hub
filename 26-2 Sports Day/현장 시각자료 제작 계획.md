## 1. 시간대별 인원 배치 보드

**목적**: 하클 41명 전원이 "지금 이 시간에 나는 어디서 무엇을 하는가"를 찾는 자료. xlsx 매트릭스는 현장에서 검색이 안 되므로 **시간 띠 × 역할 블록**으로 재편한다.

**구조 (안)**
- 오전 1장 / 오후 1장, 총 2장 분할 (41명 명단을 1장에 다 넣으면 밀도 초과)
- 오전: 09:30 명륜 집합 → 10:00 물품수령·출석체크 → 10:30 경기장 준비(구역별: 입장관리존 7 / 경기장 8 / 팀별존 8 / 본부 5 / 확인인원·총괄) → 11:50 입장·점심(→자료 ②에서 상세) → 12:50 개막 준비
- 오후: 13:00 개회 → 13:30 게임 1부(게임별 블록) → 15:10 중간 정비 → 15:50 게임 2부 → 17:35 시상 → 18:00 철거 원칙(설치자=철거자)
- 각 블록: 역할명(굵게) + 인원 수 + 명단. 상시 역할(촬영 12:00~18:10, 준비 총괄)은 하단 별도 띠
- **이름 찾기를 돕는 장치**: 우측 끝에 가나다 색인 미니 표(이름→속한 블록 번호)를 넣을지 검토 — 41명 기준 효율 확인 후 결정

**데이터 작업**: xlsx 매트릭스 → `(시간, 역할, 명단[])` JSON 변환 스크립트 (수작업 전사 대신 프로그램 추출로 전사 오차 제거)

**검증**: 각 시간대 인원 합계 vs 시트 표기(예: "총 41명") 대조 · 동일인 동시간 중복 배정 스캔 — **자료를 만들며 원본 배정표의 오류도 같이 잡는 부수 효과**

**리스크**: ① xlsx 좌측 로스터 열과 중앙 배치표의 정렬이 어긋난 구간(2행짜리 셀 병합) → 추출 후 3곳 이상 육안 대조 ② "메이플1" 같은 닉네임 그대로 유지 (원본 표기 우선)

## 2. 입장 수속 플로우차트 (11:50~12:50)

**목적**: 행사 전체에서 사람·순서가 가장 꼬이기 쉬운 1시간. 담당 20여 명이 **손매포인트와 순서**를 같은 그림으로 보게 한다. 참가자가 받는 첫인상 구간이기도 하다.

**구조 (안)** — 좌→우 수평 플로우 6단계, 각 단계 아래 담당 명단:
1. **버스 도착·인솔** (명륜 인솔 6: 김소라·박서윤·이강서·임유진·박서원·안령인) — 도착 즉시 인솔, 정보방 도착 공지
2. **출석 체크** (고연준·이주환·성현중·양서경 — 노트북)
3. **도장판 기록** (강단비·김민서·권나혜·김나은) — 기재 3종: **팀 · 티셔츠 사이즈 · 비건 여부**
4. **점심·음료 배부** (배솔비·김민정·이현서·신지나 + 줄관리 임도준·윤시현·이나원·한고은)
5. **팀 천막 안내 → 단체티 배부** (부팀장 6 + 팀장) — 도장판 기준 교환
6. **예외 처리** (성현중·양서경): 지각생 입장 · 입장료 미납→receipt · 추가 접수 대기

- 하단에 **물리 동선 미니 맵**: 버스 하차 → 입장 관리존(천막3·테이블4) → 팀 천막 — 추출해 둔 배치도 이미지 축소 활용
- 실패 분기(사이즈 불일치→즉시 보고 등)는 각 단계에 짧은 화살표 메모

**데이터**: 전 단계 확보 완료 (타임라인 시트 22~31행 + 행사기획안 시트 33~38행)

**검증**: 단계별 담당 명단이 상호 배타적인지(자료 1의 중복 스캔과 교차 검증), 도장판 기재 항목 3종 정확성

**리스크·의도된 장치**: '추가 접수 대응'은 아직 절차 미정 → **빈칸 박스로 남기고 "브리핑에서 채움" 표기** — 자료가 곧 안건이 되게 한다. 우천 시에도 입장 수속은 동일(수성관 내)이라 한 문장 병기.

## 3. 게임별 심판 카드 6종 (+공통 1종)

**목적**: 브리핑 핵심 안건(심판 배정·규칙 숙지 확인)의 진행 도구이자, 심판 20여 명이 현장에서 손에 들고 볼 참조 카드. 규칙 숙지 확인을 "읽으셨죠?"가 아니라 **카드를 같이 보며 점검**으로 바꾼다.

**구조 (안)** — 게임당 1장, 6장 + 공통 1장 = 7장
- 카드 공통 레이아웃:
  - 상단: 게임명 · 시간(경기당 소요+준비시간) · 토너먼트/메인 구분
  - 좌측: 진행 방식 (원문에서 발췌한 규칙 4~6줄 — 요약 최소화)
  - 우측 상: **점수 — 토너먼트 6등급 100/80/60/40/20/10 · 하클 팀 격파 시 +10점**
  - 우측 하: 주심 · 보조심판 · 게임 보조 (이름 그대로)
  - 하단: 판정 포인트(모호한 판정 상황) + 준비물(호루라기·점수판·가면 등)
- 공통 카드 1장: 점수 배분 표(전 종목 동일) + 하클 특별 규칙 + **집계 전달 — 본부 옆 점수집계, 고연준·이주환(노트북)** + 도장→뽑기는 미니게임만(점수 무관)
- 6종: 색깔 판 뒤집기 / 무궁화 꽃이 피었습니다 / 짝짓기 게임(메인) / 줄다리기 / Protect the Sadness! 피구 / 계주(메인)

**데이터**: 규칙 = 컨텐츠팀.docx에서 게임별 섹션 추출(④점수 부여 방식·규칙 구조 확인 완료) / 심판 배정 = 타임라인 시트 / 소요시간 = 개요·타임라인

**검증**: 카드별 규칙 문장을 원문과 대조(발췌 방식이라 왜곡 위험 낮음) · 주심명 대조 · 피구(Protect the Sadness!)는 커스텀 룰+가면 소품이라 원문 정독 필수

**리스크**: 원문 규칙이 길어 1장에 안 들어가는 게임 → 발췌 우선, 안 되면 "상세는 원문" 스크램 라인 (심판이 이미 9/16 원문을 받았다는 전제)

## 제작 순서 (오늘 안)

1. 데이터 구조화: xlsx → 인원 JSON + docx → 게임 규칙 JSON (검증 포함)
2. 자료 1 빌드(2장) → 3. 자료 2 빌드(1장) → 4. 자료 3 빌드(7장) — 총 10장
3. 렌더·QA → PNG 내보냄 → 최종 브리핑 진행용 md에 "투사 자료" 섹션 연결
4. 정정 반영 완료: 점수 6등급(100/80/60/40/20/10)+하클 +10 (진행용 md §3 수정됨)

> 승인 후 빌드 시작. 구조(띠 분할, 색인 표, 빈칸 박스)는 빌드 중 검증 결과에 따라 미세 조정할 수 있음.
