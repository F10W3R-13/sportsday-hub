# 00. 개요와 연간 사이클

이 저장소는 **스포츠데이 기획을 위한 통합 시스템**입니다. 2026-2학기 처음 도입되어
"전 스포츠데이에서 한 번도 씌어지지 않았던 방식"으로 호평을 받았고, 이후 매년
후계자가 **AI 개발 도움 없이** 이어 쓸 수 있도록 템플릿화되었습니다.

## 무엇이 들어 있나

| 위치 | 내용 |
|---|---|
| `sportsday-hub/` | **기획 허브 웹앱** (Next.js + Supabase + Vercel). 팀 지침·마일스톤·결정·이슈·인계·드라이브 파일 피드·당일 역할 조회 |
| `briefing-build/` | **브리핑 자료 제작 도구**. 발표 덱·현장 보드·치트시트를 코드로 생성 (`GUIDE.md` 참조) |
| `HANDOVER/` | 이 문서들 — 연간 운영 설명서 |
| `archive/` | **작년까지의 실제 기록.** `2026-1/`, `2026-2/` (원본 문서·최종 산출물·당시 데이터 사본) |
| `.github/workflows/` | 자동 검증(CI): PR/푸시마다 typecheck·lint·test |

git 태그 `final-2026-2` 와 브랜치 `2026-2` 는 26-2 종료 시점의 완전한 스냅샷입니다.
"작년에 실제로 어떻게 했지?"가 궁금하면 archive 폴더와 이 태그를 보면 됩니다.

## 연간 사이클

```
연초 셋업 (1~2일)          시즌 운영 (매주)              연말 마무리 (행사 후)
┌────────────────┐   ┌─────────────────────────┐   ┌────────────────────┐
│ 01_연초_셋업    │ → │ 02_콘텐츠_채우기          │ → │ 06_연말_아카이브와   │
│ 새 프로젝트 파고 │   │ (상시: 지침·마일스톤·인계)   │    인수인계          │
│ 앱 띄우고 시드   │   │ 03_당일역할_페이지 (D-2주~) │ 다음 해에게 넘기기    │
│                │   │ 04_브리핑_자료 (D-2주~)     │                    │
└────────────────┘   └─────────────────────────┘   └────────────────────┘
```

필요할 때: `05_드라이브_연동` (연초 1회 설정), `07_문제해결_FAQ`.

## 세 가지 원칙 (26-2에서 검증된 운영 철학)

1. **단일 진실 원천**: 중복 관리 금지. 앱 데이터는 DB(웹 UI에서 수정), 당일 배치는
   `data.ts`+`roster.js`, 설정은 `event-config.ts`. 문서와 어긋나면 **웹앱이 항상 승리**.
2. **수정은 만든 곳에서**: 브리핑 자료를 고치려면 결과 pptx가 아니라 `roster.js`를 고치고
   다시 빌드. 지침을 고치려면 content-source 마크다운을 고치고 다시 시드.
3. **자동 검증 믿기**: `npm test`는 오타·빠진 배정을 잡아주는 검사기다. 깨지면
   지시하는 메시지를 읽고 데이터를 고친다.
