# 00. 개요와 연간 사이클

이 저장소는 **스포츠데이 기획을 위한 통합 시스템**입니다. 2026-2학기 처음 도입되어
"전 스포츠데이에서 한 번도 씌어지지 않았던 방식"으로 호평을 받았고, 이후 매년
후계자가 **AI 개발 도움 없이** 이어 쓸 수 있도록 템플릿화되었습니다.

## 무엇이 들어 있나

| 위치 | 내용 |
|---|---|
| `sportsday-hub/` | **기획 허브 웹앱** (Next.js + Supabase + Vercel). 팀 지침·마일스톤·결정·이슈·인계·드라이브 파일 피드·당일 역할 조회 |
| `briefing-build/` | **브리핑 자료 제작 도구**. 발표 덱·현장 보드·치트시트를 코드로 생성 (`GUIDE.md` 참조) |
| `HANDOVER/` | 이 문서들 — 연간 운영 설명서 |
| `archive/` | **작년까지의 실제 기록.** `2026-1/`, `2026-2/` (원본 문서·최종 산출물·당시 데이터 사본) |
| `.github/workflows/` | 자동 검증(CI): PR/푸시마다 typecheck·lint·test |

git 태그 `final-2026-2` 와 브랜치 `2026-2` 는 26-2 종료 시점의 완전한 스냅샷입니다.
"작년에 실제로 어떻게 했지?"가 궁금하면 archive 폴더와 이 태그를 보면 됩니다.

## 연간 사이클

```
시즌 시작 (30분)              시즌 운영 (매주)              시즌 종료
┌────────────────┐   ┌─────────────────────────┐   ┌────────────────────┐
│ AI-SEASON-RESET │ → │ 02_콘텐츠_채우기          │ → │ 다음 시즌 리셋이     │
│ AI에게 리셋 시키고│   │ (상시: 지침·마일스톤·인계)   │    자동 아카이브       │
│ SQL 붙여넣기    │   │ 03_당일역할 (D-2주~)       │  (06_연말)          │
│                │   │ 04_브리핑 (D-2주~)         │                    │
└────────────────┘   └─────────────────────────┘   └────────────────────┘
인프라(Supabase/Vercel)는 하나의 영구 인스턴스 — 매년 새로 만들지 않는다.
```

필요할 때: `05_드라이브_연동` (연초 1회 설정), `07_문제해결_FAQ`.

## 세 가지 원칙 (26-2에서 검증된 운영 철학)

1. **단일 진실 원천**: 중복 관리 금지. 앱 데이터는 DB(웹 UI에서 수정), 당일 배치는
   `data.ts`+`roster.js`, 설정은 `event-config.ts`. 문서와 어긋나면 **웹앱이 항상 승리**.
2. **수정은 만든 곳에서**: 브리핑 자료를 고치려면 결과 pptx가 아니라 `roster.js`를 고치고
   다시 빌드. 지침을 고치려면 content-source 마크다운을 고치고 다시 시드.
3. **자동 검증 믿기**: `npm test`는 오타·빠진 배정을 잡아주는 검사기다. 깨지면
   지시하는 메시지를 읽고 데이터를 고친다.

## 작년 자료는 어디서 보나 (온보딩 첫날)

새 시즌 준비는 통상 **구글 드라이브의 작년 스포츠데이 폴더(워드·엑셀 원본) 열람**부터
시작한다 — 회의록·기획안·인원관리표의 **양식과 서식만 차용**해 올해 것을 새로 쓰고,
내용은 비운 상태로 시작하는 게 원칙이다.

| 위치 | 성격 |
|---|---|
| 구글 드라이브 (동아리 드라이브의 스포츠데이 폴더) | 살아있는 공유 원본 — 올해 협업도 여기서 |
| 이 저장소 `archive/<연도-학기>/` | 시즌 종료 시점의 **확정 스냅샷** + 최종 산출물(덱·보드·PNG·당일 데이터 사본) |

드라이브는 나중에 정리·삭제될 수 있으니 참고의 최종 기준은 archive 쪽이고,
반대로 드라이브에만 있는 중간 산출물도 있을 수 있으니 양쪽을 함께 뒤져볼 것.
"작년에 이걸 어떻게 했지?"가 5분 넘게 안 풀리면 git 태그(`final-2026-2` 등)까지 확대.

## 인프라 정책 (2026-2 종료 후 갱신)

- **영구 인스턴스 + 년말 리셋**: Supabase/Vercel 프로젝트는 클럽 공용 계정으로 하나만 운영하고,
  해마다 `AI-SEASON-RESET.md` 절차로 데이터를 리셋한다. (2026-2 시즌까지는 '매년 새 프로젝트'
  방식이었으나 온보딩 간소화를 위해 폐지 — 과거 시즌 보존은 드라이브 + 저장소 archive가 담당.)
- 코드는 연도 무관(템플릿) — 연도 값은 DB(app_config)가 원천. 시즌 리셋 SQL만으로 앱이 갱신된다.
