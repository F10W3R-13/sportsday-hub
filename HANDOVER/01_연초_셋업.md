# 01. 시즌 시작 — AI와 함께 30분

> **여기서부터 읽으면 됩니다.** 코딩·설치·터미널은 전혀 필요 없습니다.
> 필요한 것: 올해 기획 문서(드라이브 시즌 폴더) · AI 에이전트(ChatGPT/Claude 등 아무거나) ·
> Supabase 대시보드 접속(클럽 공용 계정).

## 시즌 시작 절차 (총 4단계)

1. **문서 준비** — 작년 시즌 폴더를 복제해 올해 내용을 채운다
   (양식 규격: `HANDOVER/양식/표준양식_규격.md` §5 "지우고 채우기")
2. **AI 호출** — AI 에이전트에게 저장소의 [`AI-SEASON-RESET.md`](../AI-SEASON-RESET.md) 와
   올해 시즌 폴더(또는 문서 첨부)를 주고 "이 절차서대로 시즌 리셋을 수행해줘"라고 한다
3. **SQL 실행** — AI가 만든 `season_reset.sql`을 Supabase 대시보드 → SQL Editor 에
   붙여넣고 Run. 맨 아래 검증 결과가 기대치와 같은지 확인
4. **앱 확인** — 허브 사이트 새로고침: 제목·D-day·팀 카드·결정 추적표가 올해 값인지.
   좌측 하단 닉네임 설정 후 마일스톤 체크 한 번으로 쓰기 동작 확인

막히면: `HANDOVER/07_문제해결_FAQ.md`. AI가 안심되지 않으면 결과물을 다른 AI에게
검토시켜도 된다(SQL은 사람이 실행 전에 읽어볼 수 있다 — 요약 주석이 맨 위에 있다).

## 시즌 중 운영

전부 웹 UI: 지침 수정·마일스톤·결정·이슈·인계·드라이브 파일. 별도 문서(`02`) 참조.

## 부록 A — 인프라 구성 (읽기만, 만질 일 없음)

시스템은 **하나의 영구 인스턴스**로 운영된다(매년 새로 만들지 않는다):
- **Supabase** (클럽 공용 계정) — 데이터베이스. 시즌 리셋 SQL만으로 해마다 갱신.
- **Vercel** — 앱 호스팅. 코드는 이미 배포돼 있고 연도 무관이라 건드릴 필요 없음.
- **구글 드라이브** — 실제 협업. 팀 폴더 파일이 앱에 자동 표시(연동 설정은 `05`).
- 연말이 곧 다음 시즌 준비: `06` 참조.

## 부록 B — 재앙 복구 (앱/DB가 완전히 죽었을 때만, 도우미와 함께)

인스턴스 자체를 잃어버린 경우에만 새로 만든다 — 코딩 가능한 도우미가:
저장소 클론 → 새 Supabase 프로젝트 → `sportsday-hub/supabase/template/000_baseline_schema.sql`
실행 → 새 Vercel 프로젝트(Root Directory `sportsday-hub`) → env 등록(`.env.local.example` 참조)
→ AI 시즌 리셋 재실행. 2026-2의 원래 셋업 기록은 git 히스토리에 있다.
