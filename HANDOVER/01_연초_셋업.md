# 01. 연초 셋업 — 새 시즌 인스턴스 띄우기

매년 **새 Supabase + 새 Vercel 프로젝트**를 만듭니다 (작년 사이트는 그대로 보존).
필요한 것: GitHub 계정(이 저장소 접근), Google 계정, 1~2시간.

## 1. 코드 받기

```
git clone <이 저장소 주소>
cd sportsday-hub
npm install
```

## 2. Supabase 프로젝트 만들기

1. https://supabase.com → New project (이름 예: `sportsday-27-1`, 무료 티어)
2. 프로젝트가 준비되면 **SQL Editor** 열고 `sportsday-hub/supabase/template/000_baseline_schema.sql`
   파일 **전체**를 붙여넣어 실행 (Run). → 테이블·RLS·트리거가 만들어진다 (아직 데이터 없음)
3. Project Settings → API 에서 다음 두 값을 복사해 둔다:
   - `Project URL` → NEXT_PUBLIC_SUPABASE_URL
   - `anon public` 키 → NEXT_PUBLIC_SUPABASE_ANON_KEY
   (드라이브 연동을 쓸 것이라면 `service_role` 키도)

## 3. 환경변수 파일

` sportsday-hub/.env.local.example`을 `.env.local`로 복사하고 Supabase 값을 채운다.
(모든 항목 설명이 파일 안 주석에 있다. 드라이브 연동 값은 05번 문서에서 나중에 채워도 된다.)

## 4. 로컬에서 띄워보기

```
npm run dev    # http://localhost:3000
```

대시보드가 뜨면(아직 팀 카드는 비어 있음) 성공. 오류가 나면 07_FAQ.

## 5. 올해 콘텐츠 시드 넣기

→ **02_콘텐츠_채우기.md** 로 이동. (event-config 수정 → content-source 작성 → migrate:md → SQL 실행)

## 6. Vercel 배포

1. https://vercel.com → Add New Project → 저장소 연결
2. **Root Directory 를 `sportsday-hub` 로 지정** (중요! 기본값으로 하면 빌드 실패)
3. Framework Preset 이 자동으로 Next.js 로 안 잡히면 수동으로 `Next.js` 선택
4. Environment Variables 에 `.env.local`의 값들을 전부 등록
   (NEXT_PUBLIC_BASE_URL 은 배포 URL로)
5. Deploy
6. 배포된 URL 접속 → 좌측 하단 닉네임 설정 → 대시보드에서 팀 카드 확인

### 자주 걸리는 것 (26-2 실제 경험)
- **Vercel Deployment Protection(SSO)** 이 켜져 있으면 외부인이 404/로그인 화면을 본다.
  Settings → Deployment Protection → Vercel Authentication 끄기.
- Framework 가 "Other"로 잡혀 빌드가 이상하면:
  `vercel project update --framework nextjs` 또는 프로젝트 설정에서 변경.
- Supabase 무료 티어는 **7일간 방문 없으면 절전**. 안 뜨면 Dashboard 에서 Restore.
