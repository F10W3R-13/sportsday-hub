# 02. 콘텐츠 채우기 — 앱에 올해 기획을 넣는 법

시즌 내내 반복하는 작업입니다. 크게 ①설정 파일 ②원본 문서 ③시드 세 가지.

## ① 연도 설정 — `sportsday-hub/lib/event-config.ts`

**새 시즌에 코드 파일 중 사실상 유일하게 손대는 파일.** 열어보면 주석으로 안내되어 있다:

- `EVENT_NAME` / `SEMESTER_LABEL` / `HUB_TITLE` — 앱 제목·표기
- `EVENT_DATE_ISO` — 행사일 ('YYYY-MM-DD'). D-데이·당일 페이지 진행상태의 원천
- `TEAM_IDS` / `TEAM_META` / `TEAM_KEYWORDS` — 팀 구성 (팀 수·이름·색·아이콘·미션)

수정 후 검증: `npm run typecheck && npm test`

## ② 기획 문서 — `sportsday-hub/content-source/`

앱에 들어갈 지침·결정·일정·이슈를 **마크다운**으로 쓴다. 파일 규격:

- `00_기획지침_마스터.md` — 전체 공유 지침 (모든 ## 섹션이 기획관리팀 지침으로 들어감)
- `teams/{content,budget,exchange,timeline}.md` — 팀별 지침

**파서가 읽는 특수 섹션** (형식을 지켜야 DB에 반영된다 — 각 파일 상단 주석에 규격 있음):

| 섹션 | 반영되는 곳 | 형식 |
|---|---|---|
| 핵심 결정 추적표 | decisions | 표. D1부터, 상태 🟢확정:/🟡방향/🔴미정/⚪보류 |
| 회의 일정 | milestones(meeting) | `- [ ] 1차 회의 (3/5)` |
| 산출물 일정 | milestones(deliverable/event) | 표. 담당에 팀명 |
| 이슈 로그 | issues | 표. 상태 open/진행/해결 |
| ## 체크리스트 (팀 문서) | milestones(상시) | `- [ ] 항목 🔴HIGH` |

## ③ 마크다운 → DB 시드

```
cd sportsday-hub
npm run migrate:md
```

→ `supabase/migrations/0005_seed_data.sql` 이 (재)생성된다.
**새 프로젝트라면** 이 파일 전체를 Supabase SQL Editor 에서 실행한다.

이미 데이터가 있는 운영 중 DB에 다시 넣을 때는 주의 — 0005는 INSERT 위주라
기존 행과 중복될 수 있다. **운영 중에는 UI에서 직접 수정하는 게 원칙**이고,
마크다운 → DB 일괄 반영은 연초 1회 + 큰 개정 때만.

보조 스크립트:
- `npx tsx scripts/update-guideline-doc.ts --dry-run` — 지침 문서(guideline_doc)만 갱신
- `npx tsx scripts/verify-guideline-sync.ts --canonical="../올해 문서 폴더"` — 원본 문서 폴더와 content-source가 같은지 검증

## 시즌 중 운영 (웹 UI에서)

- **결정 추적표 / 타임라인 / 이슈 / 인계**: 각 페이지에서 추가·수정. 누가 고쳤는지 감사로그에 남는다(닉네임).
- **닉네임**: 좌측 하단에서 최초 1회 설정. 쓰기 작업 전 필수.
- **팀 지침**: 팀 페이지 → 지침 탭에서 직접 편집 가능(마크다운 에디터 내장).
- **인계(handoffs)**: 팀 간 "이 자료 이 날까지 줘야 해" 추적. 위젯은 상태의 거울 — 앱이 아니라 실제 인계를 먼저 하고 표시를 갱신.
- **파일 피드**: 드라이브 연동(05번) 시 각 팀 폴더의 최신 파일이 대시보드에 뜬다.

## 원칙 다시 한 번

앱(DB)과 마크다운이 어긋났다? → **웹앱이 항상 최신**(SSOT). 마크다운은 초안·원본 기록.

## ⚠ 시드 후 재잠금 (잊기 쉬운 마지막 한 걸음)

`migrate:md` 시드(0005) 실행을 마쳤으면, Supabase SQL Editor 에서 마지막으로:

```sql
update app_locks set locked = true where key = 'milestones_insert';
```

베이스라인은 시드가 통과할 수 있도록 잠금을 **해제된 상태**로 만들어 둔다.
재잠금하지 않으면 "신규 항목 추가 잠금"(중복 항목 방지 장치)이 작동하지 않는다.
(잠긴 상태에서 시드를 돌리면 CHECKLIST_LOCKED 오류로 전부 롤백된다 — 그때는
`update app_locks set locked = false ...` 로 해제했다가 다시.)
