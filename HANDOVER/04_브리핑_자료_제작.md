# 04. 브리핑 자료 제작

상세 절차는 **`briefing-build/GUIDE.md`** 에 있다 — 이 문서는 전체 흐름과 일정 감각만.

## 무엇을 만드나 (26-2 기준)

1. **최종 브리핑 덱** (발표자용 pptx 18장) — 브리핑 회의(행사 전주)에서 발표
2. **현장 운영 보드** (pptx 12장 → PNG) — 현장에 세우는 안내판
3. **발표자 치트시트** (pdf/png 1장)

## 일정 감각

| 시점 | 할 일 |
|---|---|
| D-3주 | 게임 규칙·배치 초안 확정 (컨텐츠팀 원문) → roster.js 입력 시작 |
| D-2주 | 당일 페이지(03번)와 병행 — 데이터 원천을 맞춘 뒤 동시에 완성 |
| D-1주 | 1차 빌드 → 원본 명단표(엑셀)와 **이름 하나하나 대조** |
| 브리핑 회의 | 피드백 반영 → 재빌드 → 최종 |
| 행사 전날 | 보드 PNG 출력·현장 세팅, 치트시트 인쇄 |

## 작년의 교훈 (검증 절차 문서에서)

- 최대 리스크는 **명단 오타** (작년: 이강서↔유주영 3곳 오기 → 원본 대조로 적발).
  결과물 눈 대충 보지 말고 반드시 원본 표와 대조.
- 정정은 결과물이 아니라 **roster.js에서** → 양쪽(보드·덱) 재빌드.
- 원본 문서의 "겹침 배정"은 실제 결정인지 원본 오류인지 확인 후 반영
  (작년: 가짜 겹침 안건을 삭제한 사례 있음).
