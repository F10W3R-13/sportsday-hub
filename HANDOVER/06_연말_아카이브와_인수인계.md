# 06. 연말 아카이브와 인수인계

행사가 끝난 뒤 **올해 기록을 보존하고, 저장소를 다음 해를 위해 비우는** 절차.
2026-2가 끝날 때 실제로 수행했던 작업을 그대로 절차화한 것.

## 0. 시점

행사 직후~후계자 확정 사이 아무 때나. 늦어지면 기억이 흐려진다.

## 1. 올해 상태 확정 커밋

미커밋 변경(마지막 콘텐츠·코드)을 논리 단위로 커밋해 올해 최종 상태를 만든다.

## 2. 동결 브랜치 + 태그

```
git branch <올해-학기>        # 예: 2026-2
git tag -a final-<올해-학기> -m "… 스포츠데이 최종 상태 스냅샷"
```

## 3. 올해 라이브 사이트 동결

Vercel(올해 프로젝트) → Settings → Git → **Production Branch를 올해 브랜치로 변경.**
이후 main 을 밀어도 올해 사이트는 그대로 얼어 있다.

⚠ Supabase 무료 티어는 7일 무방문 시 절전 — 아카이브 사이트가 잠들어도
정상(다시 열면 Restore). 완전한 기록은 어차피 이 저장소에 있다.

## 4. 자료 아카이브

- 올해 원본 문서 폴더(예: `27-1 Sports Day/`)를 `archive/<연도-학기>/sports-day/` 로 이동 (git mv)
- 당일 페이지 실데이터(교체 전 data.ts·copy.ts)를 `archive/<연도-학기>/my-role-data/` 에 보존
- content-source 원본도 `archive/<연도-학기>/content-source/` 에 보존

## 5. 저장소 비우기 (다음 해 템플릿화)

| 대상 | 할 일 |
|---|---|
| `lib/event-config.ts` | 다음 해 예시값으로 갱신 (주석 안내대로) |
| `lib/dayof/data.ts`·`copy.ts` | 가상 인물 더미로 교체 (전 시즌 실본은 4번에서 보존됨) |
| `content-source/*.md` | 템플릿 플레이스홀더로 교체 |
| `briefing-build/roster.js` | 실명이 그대로 남아도 됨 — "폴더 복제 후 수정" 플로우(GUIDE 참조). 원치 않으면 더미화 |
| 태그 | `git tag -a template-<연도> -m "다음 해 시작 템플릿"` (선택) |

검증: `cd sportsday-hub && npm run typecheck && npm test && npm run build` 전부 통과 확인.

## 6. 커밋·푸시

main 에 "연간 템플릿화 + 아카이브" 커밋 후 푸시. 후계자에게 main 을 물려준다.

## 7. 후계자에게 (첫날 안내할 한 줄)

> "저장소 클론 → `HANDOVER/00_개요와_연간_사이클.md` 부터 읽으면 됩니다."

## 8. (해당 시) GitHub 소유권 이전

개인 계정 소유라면 졸업 전 동아리/학교 조직 계정으로 Transfer
(Settings → Danger Zone → Transfer ownership). 참여자 권한 정리.

## 9. 저장소 공개 범위 주의

이 저장소에는 실명 자료가 포함되어 있다(`archive/`, `briefing-build/roster.js`,
git 히스토리의 시드 SQL). **비공개(private) 저장소로 유지**하고, 공개 요청·
공개 저장소 이전은 실명 데이터 정리 후에만 검토할 것.
