# 06. 연말 — 아카이브와 다음 세대 인수인계

행사가 끝난 해의 마무리. 대부분 **이미 일상 속에서 처리된다**(시즌 산출물은 드라이브에,
데이터는 다음 리셋 때 자동 백업). 여기는 잊지 말 것만 정리했다.

## 1. 즉시 (행사 직후)

- 최종 산출물(브리핑 덱·보드 PNG·치트시트·사회자 대본)을 시즌 폴더에 정리 — 이미 그렇게 하고 있음
- 앱은 그대로 둔다 — 다음 시즌 리셋 전까지 작년 기록으로 열람 가능

## 2. 다음 시즌 시작 시 (= 연말 아카이브)

다음 세대가 `AI-SEASON-RESET.md` 절차로 시즌 리셋을 실행하면, 그 SQL의 1단계가
**이 시즌 전체를 `archive_prev_*` 테이블로 자동 백업**한다. 즉 연말 아카이브는
온보딩의 부산물로 자동 처리된다.

영구 보관을 원하면(권장 — 백업 테이블은 다다음 시즌에 대체됨):
- 사람이: Supabase 대시보드 → 각 테이블 CSV 내보내기 → 드라이브 시즌 폴더에 보관
- 또는 도우미가: CSV/SQL 덤프를 저장소 `archive/<연도-학기>/` 에 커밋

## 3. 인수인계 (다음 세대에게 넘기는 것)

1. **한 줄 안내**: "저장소 `HANDOVER/00`부터 읽으면 됩니다" + 허브 사이트 URL + Supabase 대시보드 접속 권한(클럽 공용 계정)
2. `AI-SEASON-RESET.md` 상단의 **시즌 폴더 링크 칸**을 올해 것으로 교체
3. (선택) 1시간 인수인계 세션: 위임자가 01절차를 한 번 같이 진행

## 4. 도우미(코딩 가능한 사람)만 하는 일 — 평시엔 불필요

- 팀 조직 개편(6팀 신설 등): `sportsday-hub/lib/event-config.ts` 의 TEAM_IDS·TEAM_KEYWORDS 1줄 추가
- 앱 기능 수정·버그 수정: 통상적인 git 워크플로(검증 `npm run typecheck && npm test && npm run build`)
- 인프라 재해 복구: HANDOVER/01 부록 B
- git 태그: 원하면 시즌 종료 시 `final-<연도-학기>` 태그(2026-2 관례)

## 5. 저장소 공개 범위 주의

실명 자료 포함(`archive/`, git 히스토리) — **비공개 저장소 유지**.
