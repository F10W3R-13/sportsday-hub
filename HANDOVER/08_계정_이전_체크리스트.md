# 08. 계정 이전 체크리스트 — 졸업 전 1회 수행

> 인수인계 마지막 단계. 클럽 공용 계정이 준비되면 이 체크리스트를 순서대로 실행.
> 각 단계는 독립적이지만 권장 순서는 아래와 같다 (의존성 최소화).

## 0. 클럽 공용 계정 준비 (아직 없다면)

- [ ] 클럽 전용 Google 계정 생성 (예: `skkuglobal.sportsday@gmail.com`)
  — 이메일 하나로 Supabase·Vercel·Google Cloud·GitHub 모두 가입 가능
- [ ] 비밀번호는 여러 후계자가 아는 방식으로 공유 (비밀번호 관리자 또는 클럽 내부 문서)
- [ ] GitHub 계정이 따로 필요하면 생성 후 이 저장소 접근 권한 부여 (Settings → Collaborators)

## 1. GitHub 저장소 이전

- [ ] 클럽 GitHub 계정을 Collaborator로 추가 (Settings → Collaborators → 초대)
- [ ] 클럽 계정으로 접속해 초대 수락
- [ ] 기존 개인 계정의 접근 권한 제거 (본인 탈퇴 전에 클럽 계정이 접근 가능한지 확인)
- [ ] (대안) Organization으로 이전: Settings → Danger Zone → Transfer to new owner
  — 개인 저장소 → 클럽 Organization 소유로 변경. 기존 URL이 바뀌므로 Vercel 재연결 필요

## 2. Vercel 프로젝트 이전

- [ ] 클럽 Google 계정으로 https://vercel.com 가입 (Continue with Google)
- [ ] 기존 계정 → Settings → General → Transfer Project
  — 대상: 클럽 Vercel 계정 (이메일로 검색)
- [ ] 클럽 계정에서 이전 수락 (이메일 또는 대시보드 알림)
- [ ] 이전 후 확인: 배포 URL 접속, 환경변수 그대로 있는지 (Settings → Environment Variables)
- [ ] 도메인이 있다면 DNS 레코드 확인 (기본 .vercel.app 도메인이면 불필요)

## 3. Supabase 프로젝트 이전

- [ ] 클럽 Google 계정으로 https://supabase.com 가입
- [ ] 기존 계정 → Project Settings → General → Transfer Project
  — 대상 조직(클럽 계정의 Personal Org 또는 새 Organization) 선택
- [ ] 클럽 계정에서 이전 수락
- [ ] 이전 후 확인: Project URL·anon key·service_role key 동일한지
  (이전하면 키가 바뀌지 않음 — 같은 프로젝트의 소유자만 바뀜)
- [ ] Vercel 환경변수의 Supabase 값이 여전히 유효한지 확인

## 4. Google Cloud Console (드라이브 연동 OAuth 클라이언트)

가장 간단한 방법: **기존 OAuth 클라이언트를 버리고 새로 만들기**

- [ ] 클럽 계정으로 https://console.cloud.google.com 접속 → 새 프로젝트 생성
- [ ] Drive API 사용 설정 (API 및 서비스 → 라이브러리 → Google Drive API → 사용)
- [ ] OAuth 동의 화면 구성 (External + drive.readonly scope)
- [ ] OAuth 클라이언트 생성 (웹 애플리케이션):
  - 승인된 리디렉션 URI: `https://<배포주소>/api/auth/google-callback`
  - `http://localhost:3000/api/auth/google-callback` (로컬 테스트용)
- [ ] 새 Client ID / Secret 확보
- [ ] Vercel 환경변수 갱신: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`
- [ ] `DRIVE_ENCRYPTION_KEY` 새로 생성 (기존 토큰은 무효화됨):
  ```
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```
- [ ] 설정 페이지에서 클럽 계정으로 드라이브 재연결

(기존 클라이언트를 이전하는 방법도 있으나 복잡 — 새로 만드는 게 15분이면 됨)

## 5. 구글 드라이브 (실제 파일)

- [ ] 시즌 폴더의 소유권을 클럽 계정에 이전하거나,
      클럽 공유 드라이브로 복사 (Google Workspace 필요)
- [ ] 개인 계정의 공유 권한 정리 (불필요한 공유 해제)

## 6. 최종 확인

- [ ] 클럽 계정으로 GitHub 저장소 접속 가능
- [ ] 클럽 계정으로 Vercel 대시보드 접속 가능 + 배포 URL 정상
- [ ] 클럽 계정으로 Supabase 대시보드 접속 가능
- [ ] 허브 사이트 정상 동작 (대시보드·팀 페이지·타임라인)
- [ ] 개인 계정의 모든 접근 권한이 더 이상 필요 없는지 확인

## 주의사항

- **이전 순서**: GitHub → Vercel → Supabase 순서 권장. Vercel이 GitHub 저장소를
  참조하므로 GitHub부터, Vercel이 Supabase를 참조하므로 Supabase는 나중에.
- **개인 계정 탈퇴 전**: 클럽 계정으로 모든 서비스에 로그인해 정상 동작하는지 반드시 확인.
- **무료 티어 한계**: Supabase 무료 티어는 조직당 2개 프로젝트. 이전 시 조직 한도 확인.
