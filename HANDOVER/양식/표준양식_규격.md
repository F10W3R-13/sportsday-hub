# 표준 양식 규격 — 시즌 폴더와 기획 문서의 뼈대

> 이 문서는 **AI 에이전트가 시즌 문서를 파싱할 때 참조하는 규격**이자,
> 후계자가 작년 폴더를 복제해 "지우고 채울" 때 지켜야 할 뼈대다.
> 규격은 26-2 실제 운영 자료에서 역설계했다.
> **뼈대(폴더 구조·시트 구성·열 위치)는 바꾸지 않고 내용만 교체하는 것이 원칙.**

## 1. 시즌 폴더 구조 (구글 드라이브)

```
<연도-학기> Sports Day/            ← 예: 27-1 Sports Day (작년 폴더 복제로 시작)
├─ 00_기획지침_마스터.md           ← 전체 공유 지침 (핵심 원천 ①)
├─ [필독!] 스포츠데이 기획 가이드라인 (doc)
├─ <연도_Fall/Spring_Sports Day> 최종기획안 및 인원관리표 (시트) ← 핵심 원천 ②
├─ <연도-학기> Sports Day 기획 일정 (시트)
├─ 1차/2차 회의록 (doc) · 회의 안건서/안내문 (md)
├─ 사회자 대본 (doc) · 최종 브리핑 덱 (pptx)
├─ 교환담당팀/ · 예산팀/ · 컨텐츠팀/ · 타임라인·인원관리팀/   ← 팀 하위 폴더
│    └─ 각 팀 지침 md + 팀별 엑셀 (예산안·인원표 등)
└─ 작년 참고용 자료/ (필요 시)
```

팀 폴더 이름은 자유롭지만 **5팀 체계(기획관리·컨텐츠·예산·교환·타임라인)를 유지**할 것
— 앱의 팀 구조와 1:1 대응. (26-2에서 타임라인 팀의 드라이브명은 '탐라/인관팀'이었으나
역할은 타임라인·인원관리.)

## 2. 최종기획안 및 인원관리표 (핵심 원천 ②) — 시트 구성

### 시트1 — 기획안 (서술)
컨셉/행사명, 일시·장소, 예산 개요, 진행 형식, 게임 목록 등을 서술형으로.
AI는 여기서 행사명·행사일·컨셉·결정 사항을 읽는다.

### 시트2 — 당일 인원 배치표 (표 — 26-2 실측 열 체계)
| 열 | 의미 | 비고 |
|---|---|---|
| D | 구분 마커 | '1부'/'2부'/'멤버' 등 블록 구분 |
| G | 시간 | `9:30~10:00` · `10:00 - 10:30` 혼용 허용 |
| H | 장소 및 일정 메모 | 병행 블록 표시 |
| I | 게임 헤더 | 게임명 + `<13:30-14:10>` 소요 |
| J | 역할 | 배치 항목명 ("역할 — 이름" 규약의 역할 부) |
| K | 인원 | 숫자 또는 '팀장/나머지' 표기 |
| L | 담당자(조장) | 첫 번째 사람 |
| M~ | 멤버 | 이후 사람들 (한 칸에 한 사람) |

규칙: 같은 시간 블록은 첫 행에만 G열 시각 → 비어 있으면 직전 행의 시각 승계.
'메이플N' 같은 지원 그룹 표기는 최종기획안의 지원 명단과 대조해 실명 치환.

### 게임 규칙 — 시트 내 섹션 또는 별도 문서
게임별: 규칙 목록 / 배정(역할—이름들) / 심판 지시 / 준비물 / 주의사항.

## 3. 00_기획지침_마스터.md — 섹션 규격

앱 시드의 직접 원천. 다음 특수 섹션이 DB에 반영된다 (형식 상세는
`sportsday-hub/content-source/00_기획지침_마스터.md` 상단 주석):

- `## 핵심 결정 추적표` (표) → decisions
- `## 회의 일정` (`- [ ] 1차 회의 (3/5)`) → milestones(meeting) — **괄호 날짜 필수**
- `## 산출물 일정` (표) → milestones(deliverable/event)
- `## 이슈 로그` (표) → issues
- 그 외 `##` 섹션 → 기획관리팀 지침 문서

## 4. AI 파싱 매핑표 (문서 → DB)

| 원천 | DB 테이블·키 | 비고 |
|---|---|---|
| 기획안: 행사명·테마 | app_config.`hub_title` / `event_name` | |
| 기획안: 일시 | app_config.`event_date_iso` | 'YYYY-MM-DD'로 정규화 |
| 학기 표기 | app_config.`semester_label` | 예: '2027년 1학기' |
| 팀 구성(이름·색·미션) | teams | 5팀 id 고정 슬러그 사용 |
| 마스터 지침 특수 섹션 | decisions / milestones / issues | §3 규격 |
| 시트2 배치표 | (2단계 예정) my-role 데이터 | 1단계는 브리핑·참고용 |

## 5. "지우고 채우기" 규칙 (후계자용 요약)

1. 작년 시즌 폴더를 통째로 복제해 이름을 올해로.
2. 각 문서를 열어 **내용(텍스트)만 지우고 올해 것을 채운다** — 시트 추가/삭제·열 이동 금지.
3. 회의가 새로 열리면 회의록을 같은 양식으로 추가.
4. 다 채웠으면 `AI-SEASON-RESET.md` 절차로 앱에 반영.

## 6. 매 학기 고정 구조 (26-2 사용자 확인)

| 항목 | 고정/변동 | 내용 |
|---|---|---|
| 배치표 시트2 구조 (시간블록→역할→담당자→멤버) | **고정** | 매 학기 동일한 열 체계. 내용만 교체 |
| 게임 유형 틀 (토너먼트형 + 메인게임 + 미니부스) | **고정(관습)** | 게임 내용은 매 학기 제로부터 새로 설계하지만 유형 분류는 관습으로 유지 |
| 행사 장소 | **1학기=명륜, 2학기=율전** | 번갈아 나옴 — GATHER 구조(버스 조/직행 조)가 학기에 따라 뒤집힘 |
| 5팀 체제 (기획관리·컨텐츠·예산·교환·타임라인) | **고정** | 조직 개편이 없는 한 유지 |

AI 에이전트 주의: 1학기(명륜 개최)에서는 **율전 조가 버스 탑승**하고 명륜 조가 현장
직행이 된다. 2학기(율전 개최)는 그 반대. GATHER 데이터 작성 시 행사 장소를 먼저 확인.
