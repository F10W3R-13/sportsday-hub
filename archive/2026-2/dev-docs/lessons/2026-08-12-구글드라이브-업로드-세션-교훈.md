- **날짜**: 2026-08-12
- **작업**: 로컬 `26-2 Sports Day` 폴더의 신규/수정 파일 14개를 구글 드라이브 동일 폴더에 업로드
- **관련 스크립트**: `.zcode/scripts/gdrive_upload.py`, `gdrive_inspect.py`, `gdrive_fix_timeline.py`
- **결과**: 업로드 성공 (사후 폴더 매핑 오류 1건 수정)

---

## TL;DR — 핵심 3줄

1. **"설정은 되어있다" ≠ "지금 동작한다"** — MCP가 config에 있어도 세션에 노출되지 않을 수 있다.
2. **개인 용도 OAuth는 무조건 "테스트 모드 + 테스터"** — 게시(publish)는 민감 스코프에서 오히려 하드 블록.
3. **외부 서비스 작업은 dry-run의 엄격함이 보험** — 자동 생성(폴더 등)은 사전 경고 필수.

## 🔧 백엔드 / 시스템 문제점

### 1. Google OAuth "테스트 vs 프로덕션" 역설 — 최대 시간 싱크
가장 큰 병목이었다. 직관과 정반대로 동작한다.

| 모드 | 동작 |
|---|---|
| **테스트** | 등록된 테스터만 접근 → 경고 화면만 넘기면 됨 ✅ |
| **프로덕션 + 미검증 + 민감 스코프** | **소유자조차 전원 차단** ❌ |

"게시했으니까 이제 다 되겠지"라는 직관이 완전히 틀렸다. 민감 스코프(`drive`)가 걸려있으면 프로덕션 = 검증 통과해야만 풀리는 하드 블록.
→ **개인/소규모 용도는 무조건 테스트 모드 + 테스터가 정답.**

### 2. "MCP 설정됨 ≠ 세션에 도구 노출됨"
`config.json`에 google-drive MCP가 등록되어 있었지만, 실제 세션 도구 목록엔 안 떴다.
- 설정값 존재와 런타임 연결은 **다른 레이어**다.
- 이걸 미리 동태 검증(log/healthcheck) 안 하면 "연결되어있다"는 가정 하에 삽질하게 된다.

### 3. 웹 클라이언트 vs 데스크톱 클라이언트 호환 불가
같은 프로젝트의 OAuth 클라이언트여도 타입이 다르면 동작이 다르다.

| 타입 | redirect_uri | 용도 |
|---|---|---|
| `web` | 고정 (Vercel 콜백 등) | 웹앱 서버사이드 |
| `installed` | localhost 동적 | 데스크톱/로컬 스크립트 |

"OAuth 클라이언트 있다 = 바로 쓸 수 있다"가 아니다. **타입까지 맞아야 한다.**

### 4. Python 인터프리터 충돌
`which python`이 LibreOffice 번들 Python을 먼저 잡아서 `ModuleNotFoundError`.
PATH 순서 하나로 전체가 깨졌다.
→ **절대경로(`/c/Users/.../Python313/python.exe`)로 핀하는 습관 필수.**

## 👤 사용자 병목 (UX / 플로우)

### 5. credentials 파일 ↔ "내가 설정 중인 프로젝트" 불일치 🔥
**가장 치명적이었다.**
- credentials 파일은 프로젝트 `236102313215`을 가리키고 있었고
- 테스터 추가 작업은 프로젝트 `646626751091`에서 진행 중이었다.

두 프로젝트가 같은 사람 소유라 콘솔에서 헷갈리기 쉬웠고, "테스터 추가했는데도 안 됨" 상태가 반복됨.

> **교훈**: 사용자에게 설정을 부탁할 땐 **"이 작업이 정확히 어느 프로젝트/리소스(ID)에 해당하는지"**를 먼저 확정해야 한다. "테스터 추가해 주세요"만으로는 부족.

### 6. 로컬 폴더명 ≠ 드라이브 폴더명
`타임라인_인원관리팀`(로컬) vs `탐라/인관팀`(드라이브).
스크립트가 이름이 없으면 자동 생성해버려서 **잘못된 폴더가 생기고**, 파일 2개를 옮기고 폴더를 치우는 사후 처리가 들어갔다.

> **교훈**: 업로드 전에 드라이브의 실제 폴더 목록을 먼저 나열해서 로컬과 비교했어야 한다. dry-run이 폴더 자동 생성 시 **경고를 띄우게** 고쳐야 한다.

### 7. "어떤 계정으로 로그인 중인가"의 불확실성
여러 구글 계정이 브라우저에 로그인되어 있으면 OAuth가 의도한 계정으로 안 간다. 사용자가 매번 확인해야 하는 것 자체가 병목.

## 🔄 프로세스 교훈

### 8. 가장 먼저 저지른 실수: 환경 파악 안 하고 한계 선언
처음에 "구글 드라이브 도구 없다"고 단정 짓고 사용자에게 선택지를 던졌다가, **사용자가 "MCP 있잖아"라고 정정**했다.
`config.json`을 끝까지 뒤져보지 않은 내 잘못.

> **교훈**: "없다"고 말하기 전에 로컬 설정/로그/캐시까지 전부 뒤져본다.

### 9. 권고가 흔들렸다 (테스터 → 게시 → 다시 테스터)
OAuth 오류 원인이 안 좁혀지는 동안 권고가 테스터 추가 ↔ 앱 게시 사이를 오갔다.
근본 원인을 먼저 확정(로그/상태 기반)하지 않고 후보만 나열하니 사용자만 왔다 갔다 하게 됨.

> **교훈**: 원인 진단을 먼저, 권고는 그 다음.

### 10. 외부 서비스 작업은 "사후 수정 비용"이 크다
업로드는 한 번에 됐지만 폴더 매핑 오류로 인해 이동 + 삭제 작업이 추가로 필요했다. 로컬 작업과 달리 되돌리기 비용이 크다.

> **교훈**: dry-run을 더 엄격하게(실제 경로 시뮬레이션까지) 만들 것.
