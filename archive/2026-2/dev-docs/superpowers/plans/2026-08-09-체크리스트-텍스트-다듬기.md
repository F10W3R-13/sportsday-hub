# 체크리스트 텍스트 다듬기 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 94개 체크리스트 항목의 텍스트를 최소 수술 원칙으로 다듬어, 담당자가 읽자마자 이해할 수 있게 만든다 (기호 풀기, 작년 참고 source 분리).

**Architecture:** 3단계 파이프라인 — (1) 94개 항목 변환표를 Markdown 파일로 생성, (2) 자동 검증 스크립트로 오타/정보손실/고유명사 훼손 체크, (3) 사용자 검토 후 마이그레이션 0009로 DB 반영. 코드 변경 없음 (UI는 이미 content/source를 렌더링).

**Tech Stack:** SQL (Supabase 마이그레이션), TypeScript (검증 스크립트), Markdown (변환표)

## Global Constraints

- **최소 수술 원칙**: 원본 문장을 최대한 보존. 진짜 안 되는 것(참조 기호, 작년 참고 분리)만 손댄다.
- **금지**: 원본 단어/뉘앙스 삭제, 임의 개선("더 자연스럽게"/"더 짧게"), 문장 구조 재작성, 작년 실적을 올해 결정으로 착각.
- **팀 줄임말 유지**: 25-2, 26-1, 하클, 율전, 명륜, 브룸, SG MAPLE, 업체명(롯데리아, 탑앤탑, 게임연구소)은 그대로.
- **기존 source 보존**: 5개 항목이 기존 source 값을 가짐 — 작년 참고 이동 시 기존 값과 병합.
- 마이그레이션 0009는 content와 source만 UPDATE (milestone_id, team_id, completed 등은 건드리지 않음).
- `npm`/`npx` 사용 (pnpm은 한글 경로에서 크래시).
- 마일스톤 UUID는 `0005_seed_data.sql` 참조 (변경 금지).

## Task 1: 94개 항목 변환표 생성

**Files:**
- Create: `.superpowers/sdd/integration/checklist-transform.md`

**Interfaces:**

**이 Task의 성격:** 코드 작성이 아닌 **콘텐츠 변환 작업**. 94개 항목 각각에 규칙 A-D를 적용. 이전 실패(정보 손실, 오타, 고유명사 훼손)를 방지하기 위해 원본을 최대한 보존.

- [ ] **Step 1: 원본 94개 항목 추출**

`0005_seed_data.sql`에서 checklist_items 섹션을 읽어 각 항목의 `id`, `team_id`, `content`, `source`를 추출한다. 팀별로 정렬 (content → budget → exchange → timeline), 각 팀 내에서는 sort_order순.

- [ ] **Step 2: 변환표 파일 생성**

`.superpowers/sdd/integration/checklist-transform.md` 생성. 각 항목을 아래 형태로 작성:

```markdown
### [team_id] — sort_order N

- **ID:** `{uuid}`
- **원본 content:** `{원본 content}`
- **새 content:** `{다듬은 content}`
- **새 source:** `{이동된 source 또는 기존 source 병합, 없으면 NULL}`
- **변경 유형:** `{기호 풀기 / 작년 참고 분리 / 전문용어 풀기 / 변경 없음}`
```

- [ ] **Step 3: 각 항목에 규칙 적용 (94개)**

각 항목에 대해 아래 체크리스트를 순서대로 적용:

1. **작년 참고 분리 (규칙 C):** content에 `(25-2: ...)`, `(26-1: ...)`, `(작년: ...)` 패턴이 있는가?
   - 있으면 → 괄호 안 내용을 source로 이동, content에서는 괄호 제거
   - 작년 실적 수치(탑앤탑 단가 12,400원, 버스 80석 등)도 source로
   - 기존 source가 있으면 병합 (예: "26-1 돈까스도시락 호불호 피드백" + 새 작년 참고)
2. **참조 기호 풀기 (규칙 A):** D1-D7, §3, §3-1, 종속, 보전 한도, 주 템플릿이 있는가?
   - D1→행사 컨셉, D2→팀 개수, D4→입장료, D5→점심 메뉴, D6→단체티, D7→점수 배분
   - §3→지침의 게임 양식, §3-1→지침의 성별 항목 안내
   - 종속→의미 풀기 또는 중복이면 생략
3. **고유명사/팀 줄임말 확인 (규칙 B, D):** SG MAPLE, 25-2, 하클, 율전, 명륜, 브룸, 업체명이 훼손되지 않았는가?
4. **금지 사항 확인:** 원본 단어 삭제 없음? 문장 구조 재작성 없음? 작년 실적을 올해 결정으로 착각 없음?

- [ ] **Step 4: 자체 교차 검증**

변환표 작성 후 각 항목에서:
- 원본의 핵심 명사/숫자/고유명사가 새 content에 보존됐는지 눈으로 대조
- 정보가 빠지거나 의미가 바뀐 항목은 수정
- 특히 주의: 이전 실패 사례 (불고기버거→불고아버거 오타, "최소" 누락, 탑앤탑을 확정으로 착각)

## Task 4: DB 마이그레이션 작성 + 적용

**Files:**
- Create: `sportsday-hub/supabase/migrations/0009_refine_checklist_content.sql`

**Interfaces:**
- Consumes: `.superpowers/sdd/integration/checklist-transform.md` (사용자 승인된 최종 변환표)
- Produces: 마이그레이션 0009. 클라우드 DB에 적용 후 94개 항목의 content/source가 새 값으로.

**이 Task의 성격:** 사용자가 승인한 변환을 DB에 반영. 되돌리기 가능 (0005 원본 보존됨).

- [ ] **Step 1: 마이그레이션 파일 생성**

`sportsday-hub/supabase/migrations/0009_refine_checklist_content.sql` 생성:

```sql
-- 0009: 체크리스트 항목 텍스트 다듬기
-- 94개 항목의 content와 source를 일괄 UPDATE
-- 원본은 0005_seed_data.sql에 보존됨 (되돌리기 가능)

BEGIN;

-- 각 항목을 id로 식별하여 content와 source 업데이트
-- 변경이 없는 항목도 포함 (일관성 위해 전수 UPDATE)
UPDATE public.checklist_items SET content = '{새 content}', source = {NULL 또는 '새 source'} WHERE id = '{uuid}';
-- ... (94회, 변환표에서 하나씩 생성)

COMMIT;
```

변환표(`checklist-transform.md`)의 각 항목에서 id, 새 content, 새 source를 읽어 UPDATE 문 생성. source가 NULL이면 `source = NULL`, 값이 있으면 `source = '값'`.

- [ ] **Step 2: 마이그레이션 파일 검증**

생성된 SQL에서:
- UPDATE 문이 정확히 94개인지 확인
- 각 id가 `0005_seed_data.sql`의 checklist_items id와 일치하는지
- content에 작은따옴표가 있으면 `''`로 이스케이프됐는지
- BEGIN/COMMIT으로 트랜잭션 묶였는지
