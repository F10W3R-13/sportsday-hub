# 소관 월권 방어 설계 — 2026-08-09

> 사건: 26-2 2차 회의 문서에서 "교환·국제처" 블록 통합으로 교환담당팀에
> 국제처 컨택이 월권 할당됨. 본 설계는 (1) 이미 틀린 부분을 바로잡고,
> (2) 같은 사건이 재발하지 않도록 구조적 방어를 세운다.

## 사건 진단 (3중 구조)

| 층위 | 문제 | 증거 |
|---|---|---|
| **① 빈 공간 (근본)** | "국제처"가 마스터 어느 팀에도 소관 등록 안 됨 | 마스터 53행은 예산 배경 설명에서만 언급. 조직도(21-30행) 5팀 어디에도 "국제처" 없음 |
| **② 복제 (전파)** | "교환·국제처" 통합 블록 → 사전공유에 교환 소관으로 오번역 | 2차회의-수정안 design 139행 "(A4+A5 통합)"이 시초 |
| **③ 무방비 (재발 위험)** | 회의/사전공유 문서가 마스터 조직도와 대조되는 검증 고리 없음 | `verify-guideline-sync.ts`는 파일 동기화만 검증, 소관 정합성은 검증 안 함 |

**근본 원인**: "국제처"가 어느 팀에도 속하지 않는 빈 공간이었기에, 회의 묶기 편한 방향으로 가까운 팀(교환담당팀)으로 떨어질 수 있었다.

## 외부 기관 컨택의 실제 구조 (원본 근거)

외부 기관 컨택은 단일 팀 소관이 아니라 임원진 영역이다:

```
[요청 정리: 각 실무팀]  →  [중계·착수: 기획관리팀장=기획부장]  →  [실행: 임원진(기관팀) 공식계정]
```

| 출처 | 증거 |
|---|---|
| 25-1 체크리스트 기획관리 | "first aid 섭외 **기획부장에게 전달**" |
| 25-1 체크리스트 예산안 | "**기획부장 통해** 국제처 컨펌 후 구매 진행" |
| 가이드라인 (26-1·26-2) | "공식 계정 통해 컨택한 것들 **기관팀** 단톡에 공유" |

**"총학"·"시설관리팀"은 스포츠데이 기획 팀이 아니다.** 26-1 최종기획안 준비물 시트 "출처" 컬럼에만 등장하는 값으로, 하이클럽이 물품을 빌리는 학교 외부 조직이다. 스포츠데이 기획 조직은 기획관리팀·컨텐츠팀·예산팀·교환담당팀·타임라인/인원관리팀 5개뿐이다.

## 설계 — 5개 섹션

### 섹션 1: 소관 매핑 구조

단순화된 2층 구조. 5개 스포츠데이 팀의 직접 소관 + 외부 컨택(5팀 밖).

```yaml
# 5개 스포츠데이 기획 팀의 직접 소관
teams:
  기획관리팀:
    owns: [기획 총괄, 팀 간 조율, 최종기획안 작성]
  컨텐츠팀:
    owns: [게임 구성, 규칙, 배치도, 게임별 필요 인원, 게임 물품 리스트]
  예산팀:
    owns: [예산안 작성, 입장료 책정, 식사·간식, 단체티, 준비물 리스트]
  교환담당팀:
    owns: [구글폼, 참여자 명단, 교환 팀 배정, 카드뉴스, 교환학생 정보방]
  타임라인/인원관리팀:
    owns: [타임라인, 하클 인원 배치, 명륜 버스, 귀환 셔틀]

# 외부 컨택 — 5팀 소관 아님 (임원진/기관팀 경유)
external_contacts:
  대상: [국제처, 총학, 시설관리팀, 동아리 보전]
  실행주체: 임원진(기관팀) 공식계정 경유
```

**설계 원칙**:
- "직접 소관(teams)" vs "외부 경유(external_contacts)" 분리 → 월권 방어 핵심
- 빈 공간을 허용하지 않음 — 모든 업무는 5팀 중 하나 또는 외부로 분류
- 매핑은 사람이 읽을 수 있고(YAML 블록) 스크립트가 파싱 가능(정규 구조)

**근거 한계 (원본에 명시 없음 → 다음 전사문에서 확정)**:
- 동아리 보전: 파악은 예산팀 / 집행은 임원진일 가능성. 일단 외부로 분류.
- 총학·시설관리팀: 준비물 "출처"로만 확인. 컨택 라인 미확정이나 외부 기관임은 확실.

### 섹션 2: 즉각 수정 — 이미 틀린 부분 바로잡기

재발 방지 메커니즘과 별개로, 현재 틀린 문서를 원본 진실에 맞추는 작업.

**① 안건서(진행용)** — `26-2 Sports Day/2차 회의 안건서 (진행용).md`

- 보고 란: "국제처 컨택 사항 (임원진 경유)" 제거, "국제처 소관 아님(임원진/기관팀 경유, 기획관리팀 착수)" 안내 한 줄 추가

**② 사전공유(교환담당팀)** — `26-2 Sports Day/교환담당팀/2차 회의 사전 공유 (교환담당팀용).md`

**③ 안내문** — `26-2 Sports Day/2차 회의 안내문.md`
- 수정 불필요 (이미 64-68행에 국제처 없음 — 진본에 가장 가까웠음)

### 섹션 3: 검증 스크립트 — `verify-scope-ownership.ts`

기존 `verify-guideline-sync.ts`(파일 동기화 검증)와 같은 패턴으로, 그 옆에 소관 정합성 검증 스크립트 추가.

**파일**: `sportsday-hub/scripts/verify-scope-ownership.ts`
**실행**: `npx tsx scripts/verify-scope-ownership.ts`

**입력**:
1. 매핑 진본 — 마스터 지침의 YAML 블록에서 파싱
2. 검증 대상 — 회의 관련 마크다운 (안건서, 사전공유, 안내문)

**검증 로직**:
1. 매핑 YAML 파싱 → `{ 팀: [소관 키워드], external: [국제처, 총학, ...] }`
2. 검증 대상 문서에서 "담당/소관/준비/발표 담당" 표의 각 행 추출
3. 각 담당 항목 검증:
   - (a) 업무 설명에 외부 키워드(국제처 등)가 나오는데 담당 팀이 5팀 중 하나 → ❌ 월권 의심
   - (b) 업무 설명 키워드가 담당 팀 소관 키워드와 매칭 안 됨 → ⚠️ 소관 불일치
4. 결과 출력, 불일치 시 exit 1

**키워드 매칭의 한계와 완화**:
- 부분문자열 매칭으로 "구글폼" vs "구글 폼" 표기 변이를 놓칠 수 있음
- 매핑 YAML에 동의어를 허용해 완화: `owns: [구글폼, 구글 폼, Google Form, ...]`
- 완벽한 자연어 이해는 불가능하나, "국제처가 교환담당팀에 들어간다" 같은 명백한 월권은 키워드 매칭으로 충분히 포착 (이번 사건이 정확히 그 케이스)

**검증 범위**:

| 검증 O | 검증 X |
|---|---|
| 외부 키워드(국제처)가 5팀에 할당된 경우 | 자연어의 미묘한 뉘앙스 |
| 담당 팀과 소관 키워드 불일치 | 회의 진행 순서의 적절성 |
| 매핑 YAML 문법 오류 | 업무 중복(두 팀이 같은 키워드) |

**패키지.json 통합**:
```json
"scripts": {
  "verify": "tsx scripts/verify-guideline-sync.ts && tsx scripts/verify-scope-ownership.ts"
}
```

### 섹션 4: 회의 전사문 기반 매핑 유지보수 워크플로우

매핑 유지보수 부담을 "전사문 → AI 분석 → 매핑 갱신" 루프로 해결.

**워크플로우 (매 회의 후 1사이클)**:
1. 사용자: 회의 전사문 제공 (메시지 붙여넣기 또는 파일)
2. AI: 전사문 분석 → 매핑 변경 제안 (diff 형태)
3. 사용자: 제안 승인/거부/수정
4. AI: 마스터 매핑 YAML 갱신 + 커밋 + content-source 동기화 + 검증 스크립트 실행

**AI가 판별하는 4가지 패턴**:

| 패턴 | 예시 | AI 제안 |
|---|---|---|
| A. 새 업무 키워드 | "수금 부스는 교환담당팀이 운영" | `exchange: +수금` 제안 (근거 표시) |
| B. 소관 이동 | "단체티 발주 예산팀 → 기획관리팀 이관" | 매핑 변경 + 이전 회차 메모 |
| C. 외부 기관 등장 | "학생복지팀에서 간식 지원" | 외부 컨택 대상에 추가 |
| D. 월권 징후 | "교환담당팀이 천막 업체 선정" | ⚠️ 경고 — 천막은 외부/예산팀 영역 |

**안전장치**:
1. 근거 필수 — 모든 변경 제안은 전사문 해당 문장 인용
2. 사용자 승인 게이트 — AI는 제안만, 반영은 사용자 OK 후
3. 동의어 확장만 자동 — "구글폼↔구글 폼" 표기 변이는 자동 병합, 소관 재할당은 반드시 승인
4. 커밋 메시지에 근거 명시 — `feat(mapping): exchange +수금 (전사문 8/9 회의)`

**전사문 아카이브**:
- 경로: `26-2 Sports Day/회의록/`
- 매핑 YAML 주석으로 "근거: 회의록/2026-08-09 2차 회의 전사.md" 명시

**2중 방어**: 전사문 단계(패턴 D)에서 1차 감지, 놓치면 다음 회의 문서 작성 시 스크립트(섹션 3)가 2차 감지.

### 섹션 5: 마스터 지침 원칙

마스터 지침 말미(기존 '전역 원칙' 섹션 다음)에 새 층위 "소관 관리" 2개 섹션 추가.

**추가 위치**: `26-2 Sports Day/00_기획지침_마스터.md` 말미

**추가 내용 1 — 🔐 소관 매핑 블록**:
- 섹션 1에서 정의한 YAML 매핑 전체
- 사람이 읽을 수 있고 스크립트가 파싱 가능한 단일 진본

**추가 내용 2 — 📝 회의/사전공유 문서 작성 원칙 2개**:

원칙 1. **담당 항목은 소관 매핑과 대조한다**
- 회의 안건서·사전공유·안내문의 "담당/준비/발표 담당" 항목은 작성 전 매핑과 대조
- 왜: 26-2 2차 회의 "교환·국제처" 블록 통합 사건. 빈 공간이 매핑 대조 없이 가까운 팀으로 떨어짐.
- 검증: `npx tsx scripts/verify-scope-ownership.ts`

원칙 2. **회의 블록은 단일 팀 원칙**
- 안건서 발표 블록 이름은 단일 팀명. "교환·국제처"처럼 복수 안건을 병기하지 않는다.
- 발표 시간 압축이 필요하면 같은 팀의 안건끼리만 묶는다.
- 왜: 블록명에 복수 안건을 병기하면 "담당도 병기됐다"로 오해. 이번 사건의 직접적 원인.

**기존 원칙과의 관계**: 매핑 YAML(정적 사실)과 작성 원칙(영구 원칙)은 둘 다 지침 영역에 부합. 기존 "지침은 원칙만, 상태는 웹앱에"와 충돌 없음.

## 성공 기준

1. **이번 사건 회수**: 안건서·사전공유에서 교환담당팀에 국제처가 할당된 내용이 제거됨
2. **빈 공간 제로**: 마스터 매핑에 5팀 소관 + 외부 컨택이 명시되어, 어느 팀에도 속하지 않는 업무가 없음
3. **자동 검증**: `verify-scope-ownership.ts`가 외부 키워드의 팀 할당을 잡아냄
4. **지속 가능한 유지보수**: 회의 전사문 기반 AI 매핑 갱신 루프가 매핑을 최신으로 유지
5. **수동 방어**: 마스터 작성 원칙 2개가 문서 작성자의 인식을 강화
