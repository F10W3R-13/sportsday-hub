# 설계: 긴급 체크리스트 → 팀 체크리스트 딥링크

**날짜**: 2026-08-14
**범위**: 대시보드 '긴급 체크리스트' 위젯 항목 클릭 → 해당 팀 워크스페이스의 체크리스트 탭이 열리며 해당 항목으로 스크롤 + 잠깐 하이라이트.
**확정 동작**: A안 — 부드러운 스크롤(화면 중앙) + 약 2.5초 원샷 하이라이트 후 자연 소멸. 편집창 자동 오픈 없음.

---

## 1. 배경 / 문제

긴급 위젯 항목은 현재 눌러도 반응 없는 정적 `<div>`다. "이 항목이 실제 체크리스트 어디에 있지?"를 확인하려면 사이드바에서 팀 워크스페이스 진입 → 체크리스트 탭 클릭 → 마일스톤 그룹 사이에서 눈으로 찾아야 한다. 게다가 팀 페이지의 탭이 `defaultValue="overview"` 내부 상태라 **URL로 탭을 지정할 방법 자체가 없다.**

## 2. 목표 / 비목표

**목표**
- 위젯 항목 클릭 → `/team/{teamId}?tab=checklist&focus={itemId}` 이동.
- 도착 시: 체크리스트 탭 활성 + 해당 항목 **화면 중앙 부드러운 스크롤** + **2.5초 하이라이트 후 소멸**.
- URL이 진실 원천이라 링크 공유·새로고침·뒤로가기가 자연 동작.

**비목표 (안 함)**
- 편집 다이얼로그 자동 오픈(C안) — 사용자 의도와 다를 수 있어 기각.
- 다른 위젯(마감 마일스톤 등)으로 확장 — 긴급 체크리스트만(YAGNI).
- RTL+jsdom 컴포넌트 테스트 인프라 도입 — 별도 작업.
- 데이터/API/DB 변경 — 없음. 순수 프런트엔드.

## 3. 아키텍처 — URL 쿼리가 단일 진실

```
[위젯 항목 클릭]
  └─ Link → /team/budget?tab=checklist&focus=item-42
       └─ TeamTabs: ?tab 값으로 탭 제어 (URL이 진실 원천, 로컬 탭 state 없음)
            └─ ?focus 값 → ChecklistPanel에 focusItemId 전달
                 ├─ useEffect: #checklist-item-item-42 scrollIntoView(center, smooth)
                 └─ 해당 행에 .checklist-focus-flash 클래스 → CSS 원샷 애니메이션(2.5s) → 자연 소멸
[탭 수동 클릭]
  └─ onValueChange → router.replace(?tab={value}, focus 제거) → URL·탭 항상 일치
```

- 접근 방식 후보 중 해시 프래그먼트(Radix 탭 마운트 시점과 충돌), 세션스토리지 handoff(공유·뒤로가기 붕괴)는 기각됨.

## 4. 컴포넌트 변경

**`lib/checklist-focus-url.ts` (신규, 순수함수)**
- `buildChecklistFocusUrl(teamId: string | null | undefined, itemId: string): string | null`
- teamId 없으면 null 반환(링크 렌더 안 함 판단에 사용). 단위테스트 대상.

**`components/dashboard/urgent-checklist.tsx`**
- 각 행을 `buildChecklistFocusUrl` 결과로 `<Link>` 감쌈(null이면 현행처럼 비클릭 `<div>` 유지).
- hover 시 배경 밝아짐(`hover:bg-accent`) + `cursor-pointer`로 클릭 가능성 표시.

**`components/team/team-tabs.tsx`**
- `useSearchParams()`로 `tab`·`focus` 읽음. 탭 value는 **URL에서 직접 파생**(로컬 state 중복 없음): 유효 값이면 그 탭, 아니면 `'overview'` 폴백.
- `onValueChange` → `router.replace(\`?tab=${value}\`, { scroll: false })` — focus는 제거(수동 전환에서 과거 포커스로 재스크롤 방지).
- `useSearchParams`는 정적 페이지(`generateStaticParams`)에서 Suspense 경계 필수 → 파일 안에서 `TeamTabsInner`(기존 로직)와 `TeamTabs`(`Suspense` 래퍼)로 분리.
- `focusItemId`를 `ChecklistPanel`에 전달.

**`components/team/checklist-panel.tsx`**
- 신규 prop `focusItemId?: string | null`.
- 각 항목 행에 `id={`checklist-item-${item.id}`}` 앵커 + 조건부 클래스.
- `useEffect([focusItemId])`: `document.getElementById`로 요소 찾아 `scrollIntoView({ behavior: 'smooth', block: 'center' })`. 요소 없으면(삭제된 항목 등) 조용히 무연산. setState 없음(set-state-in-effect 회피).

**`app/globals.css`**
- `@keyframes checklistFocusFlash`: 테두리 링이 서서히 빛났다(2.5s ease-out, 1회) 사라지는 원샷 애니메이션. `animation-fill-mode: forwards`로 끝나면 완전 투명 — JS 타이머·클래스 제거 코드 불필요.

## 5. 엣지케이스

| 상황 | 동작 |
|------|------|
| `team_id` 없는 위젯 항목 | 링크 렌더 안 함(현행 비클릭 행 유지) |
| `?tab=` 유효하지 않음/없음 | `'overview'` 폴백 |
| `focus` 항목이 목록에 없음(삭제·데이터 불일치) | `getElementById` null → 조용히 무시 |
| 포커스 항목이 '상시' 그룹 | 그룹 순서 무관 앵커 스크롤로 정상 도착 |
| 수동 탭 전환 후 새로고침 | `?tab` 유지 + focus는 이미 제거돼 재스크롤 없음 |
| 딥링크 URL 새로고침 | 스크롤+하이라이트 재현(공유 링크 관점에서 자연스러움) |
| 같은 팀 페이지 안에서 동일 링크 재클릭 | 위젯은 대시보드에만 있어 항상 페이지 이동(remount) → 재강조됨. 시나리오상 문제 없음 |
| 모바일 등에서 요소가 뷰포트 가장자리에 걸림 | `block: 'center'`로 완화 |

## 6. 테스트

- **순수함수**: `tests/checklist-focus-url.test.ts` — URL 조합 정확성, teamId null → null 반환.
- **스크롤·하이라이트·탭 제어**: 컴포넌트 동작이라 수동 검증(RTL 인프라 부재 — Phase 2와 동일 제약).
  1. 위젯 항목 클릭 → 해당 팀 체크리스트 탭 열림 + 항목 중앙 스크롤 + 하이라이트
  2. 하이라이트 2.5초 후 자연 소멸, 이후 재노출 없음
  3. 다른 팀 항목 클릭 → 그 팀·항목으로 정상 이동
  4. 탭 수동 전환 → URL 갱신 확인, 새로고침 시 그 탭 유지·재스크롤 없음
  5. `?tab=foo`(무효) 직접 입력 → 개요 폴백

## 7. 유지보수 노트

- 탭 상태가 URL로 이사함 — 이후 탭 관련 기능(딥링크·복원)은 `?tab` 기준으로.
- 앵커 id 규칙 `checklist-item-{id}` 전역 유일 가정 — 다른 컴포넌트 재사용 시 주의.

## 8. 위험 / 완화

| 위험 | 완화 |
|------|------|
| `useSearchParams` + 정적 페이지 → Suspense 없으면 빌드 에러 | team-tabs.tsx 안에서 래퍼로 Suspense 명시 |
| Radix `TabsContent` 비활성 언마운트와 스크롤 시점 괴리 | controlled value라 첫 렌더부터 checklist 활성 → effect는 항상 마운트 후 실행 |
| `router.replace`로 히스토리 오염 | replace(히스토리 안 쌓음) + `scroll: false`(스크롤 점프 방지) |
| 낡은 `?focus` 잔류로 뜻밖은 재스크롤 | 수동 탭 전환 시 focus 제거 + 새로고침 재현은 의도된 동작 |
