### 스텝 3 — 프로그램 판정
```python
from pptx import Presentation
for f, n in [("26-2 Sports Day/최종 브리핑 덱 (발표자용).pptx", 17), ("26-2 Sports Day/현장 운영 보드.pptx", 11)]:
    prs = Presentation(f)
    slides = list(prs.slides)
    notes = sum(1 for s in slides if s.has_notes_slide and s.notes_slide.notes_text_frame.text.strip())
    print(f.split("/")[-1], "슬라이드:", len(slides), "노트:", notes, "기대:", n)
```

## 4. 알려진 함정 (이전 세션 실측 사례)

1. **비전 모델 OCR 오독 패턴** — 소형 한국어 텍스트에서 '중복→증복', '촬영→활영', '숙지→속지', '프로그램→포로그램', '하클→하틀' 오독 관측. 빌드 리터럴 대조 결과 전부 정상 텍스트였음. → 오탈자 판정은 반드시 소스 코드/원문 대조로 확정.
2. **빨간 픽셀 2종** — 배치도 하단 넓은 빨간 밴드 = ANGER 팀 구역 마커(정상). 결함은 '입장준' 아래 얇은 물결밑줄뿐, 제거 완료(272→0 픽셀).
3. **무궁화 행 경계선** — 오후 보드 `무궁화 14:10~14:50` 행은 폭 추정 9.82/9.85로 빌드 경고가 뜨지만 렌더상 한 줄 확인됨(추정기 보수적). 비전으로 '한 줄'이면 PASS.
4. **LibreOffice 폰트 치환** — 맑은 고딕 없는 환경에선 대체 폰트로 렌더되어 폭 판정이 달라질 수 있음. 최종 폭 판정은 실제 PowerPoint에서.
5. **서브에이전트 타입** — `document-skills:judge`는 로컬 PNG을 열지 못함(CDN 업로드만 되고 이미지 미전달). `general-purpose`는 reasoning 설정 오류로 기동 불가(실측). **vision 검증은 `Explore` 타입 사용 — 정상 작동 확인됨.** 상위 모델이 직접 vision이 있다면 스텝 2를 본인이 수행하는 게 최선.

## 6. 수정 프로토콜 (FAIL 발생 시)

1. **텍스트 내용** → 명단·게임·배치 데이터는 `roster.js`(단일 원천)만 수정 — board.js와 briefing_deck.js는 자동 반영. 렌더 문구(헤더·srcNote 등)는 각 파일 리터럴 수정
2. **레이아웃** → `band()`(일반) / `bandC()`(오후 보드 전용 컴팩트) 헬퍼의 PITCH·헤더 높이 조정. 통과한 슬라이드에 영향 주지 않도록 bandC는 오후 보드 전용 유지
3. 재빌드: `node board.js && node briefing_deck.js` (pptxgenjs는 `_briefing_build/node_modules` 로컬 설치) — `assemble.py`는 구조 분기 이전 유물로 **폐기**(실행 금지, 실행하면 deck을 board에서 재조립해 덱 전용 슬라이드가 사라짐)

5. PNG 재내보내기 시 `현장 보드 이미지/` 네이밍 규칙 유지
6. 브리핑에서 결정된 사항(결정 6건)은 **원전(xlsx·마스터 지침 md)에 먼저 반영 후** 자료 재빌드 — 자료가 진본을 앞서지 않게
