# 카톡 방송문 스타일 가이드 (22:00 드라이브 업데이트 방송)

> 이 문서는 21:40 방송문 작가(Hermes 크론)가 반드시 읽고 따라야 하는 편집 기준이다.
> 목표: 팀원이 카톡을 **skim하면서도 무엇이 어떻게 바뀌었는지 바로 이해**하게 만드는 것.
> 숫자 나열이 아니라 **의미를 문장으로** 쓴다.

## 톤과 문체

- 해요체로, 짧은 문장. ("~됐어요", "~으로 바뀌었어요", "~을 추가했어요")
- 이모지는 구조 표시용만: 📂(제목) 🆕(신규) ✏️(수정) 📄(카드) 🔗(링크). 장식 이모지 금지.
- 수치는 쓸 수 있지만 **반드시 문장 속에서 의미와 함께**: `집합 인원을 4명→2명으로 줄였어요` (O) / `4 → 2` (X)
- 기계 diff 토큰을 그대로 노출 금지: `105행 → 118행`, `621,640B`, `강단비 (+)`, `미세 변경` 같은 조각.
  - 행 수 변화는 "규모를 ~행으로 늘려 재구성했어요" 정도로만.
  - 바이트 수는 절대 쓰지 않는다. 신규 이미지/PDF는 "무슨 용도의 파일인지" 한 줄로.
  - 동일 패턴 반복(출석부에 이름 16개 추가 등)은 **한 줄로 뭉친다**: "하이클럽 팀원 16명 명단이 새로 등록됐어요 (강재희·고연준·권재현 등)"
- diff가 문장 중간 조각으로 부서져 있으면(예: `주심1명: ... → 주심1명:`) 조각을 나열하지 말고
  old/new 원문을 직접 읽고 **바뀐 내용을 문맥으로 서술**한다. 판단이 안 서면 "일부 문구가 다듬어졌어요"로 요약.

## 실전 예시 노트

- 이 예시의 숫자·명단·시트명은 실제 9/10 diff에서 왔다. 작가도 항상 old/new 원문에서만 근거를 뽑는다.
- '배치도 항목을 뺐다 — 이미지로 관리'처럼 **여러 파일의 변화를 연결한 서술**은 좋은 해요체 카드의 핵심이다. 단, 근거가 없는 연결은 하지 않는다.
- '심판 문구를 주심 1명 기준으로 통일' 같은 문장은 부서진 diff 조각을 원문 대조로 재구성한 것 — 재구성이 불가능하면 "일부 문구가 다듬어졌어요"로 솔직하게 쓴다.


## 절대 금지

1. `N행`, `N,B`, `시트 N개 — ... N행` 같은 기계 요약을 그대로 노출
2. 같은 종류 변화를 이름마다 한 줄씩 반복 나열
3. `A: → B:` 형태의 부서진 diff 조각 출력
4. "구조 개편(N행 → N행) — 주요 수치는 문서 확인" 같은 무정보 문장
5. 문장·카드 중간에서 자르기 (통 분할로 흡수)
