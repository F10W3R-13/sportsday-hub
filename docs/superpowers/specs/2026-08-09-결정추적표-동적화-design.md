# 결정 추적표 동적화 설계

**날짜:** 2026-08-09
**브랜치:** `feat/결정추적표-동적화`

## 배경

핵심 결정 추적표(D1~D7)는 시드 마이그레이션에서 고정된 7개 항목으로 생성되며, 사용자는 웹 UI에서 `current_value` 인라인 편집과 `status` 드롭다운 변경만 할 수 있다. 항목 추가/삭제 UI와 mutation이 전무하여, 행사 진행 중 발생하는 새로운 중대 결정을 담을 방법이 없다. 또한 확정(confirmed) 처리에 부수 효과가 없어, "남은 결정"이 무엇인지 한눈에 들어오지 않는다.

checklist_items는 `useAddChecklistItem` / `useDeleteChecklistItem` / `useToggleCheck` / `useUpdateChecklistItem` 4개 훅으로 CRUD를 지원하지만, decisions는 `useUpdateDecision` 1개뿐이다.

## 목표

1. 결정 항목을 웹 UI에서 **추가/삭제**할 수 있게 한다.
2. 확정된 결정을 자연스럽게 아래로 밀어내어 **미확정 결정을 상단**에 노출한다.
3. 기존 checklist CRUD 패턴을 그대로 따라 코드 일관성을 유지한다.

## 비목표 (YAGNI)

- 정렬 순서 수동 변경(드래그 앤 드롭) — 동적 정렬이 우선
- `notes` 편집 UI — 현재도 노출되지 않음
- `options` 배열 표시/편집 — UI에 표시된 적 없음
- `decision_date` 편집 — 현재 표시되지 않음

## 스키마 변경

**없음.** RLS(`0002_rls_policies.sql`)가 이미 decisions에 대해 INSERT/DELETE를 허용하고, soft-delete용 `deleted_at` 컬럼도 `0003_audit_softdelete.sql`에 존재한다. 애플리케이션 계층만 추가하면 된다.

## 설계

### 1. 정렬 순수 함수 — `lib/decisions-sort.ts` (신규)

`computeProgress`와 같은 순수 함수 패턴. DB의 `sort_order`는 건드리지 않고 화면 렌더링 시에만 정렬.

```ts
import type { Decision } from '@/lib/types/models'

/**
 * 결정 항목을 미확정 우선으로 정렬한다.
 * - 미확정(discussing/pending/deferred): sort_order 오름차순으로 상단
 * - 확정(confirmed): sort_order 오름차순으로 하단
 * sort_order 자체는 변경하지 않는다(읽기 전용 정렬).
 */
export function sortDecisions(decisions: Decision[]): Decision[] {
  return [...decisions].sort((a, b) => {
    const aConfirmed = a.status === 'confirmed' ? 1 : 0
    const bConfirmed = b.status === 'confirmed' ? 1 : 0
    if (aConfirmed !== bConfirmed) return aConfirmed - bConfirmed
    return a.sort_order - b.sort_order
  })
}
```

### 2. Mutation 훅 — `lib/mutations/decisions.ts` (확장)

기존 `useUpdateDecision`에 2개 훅 추가. 방금 도입한 `onSuccess` 패턴(invalidate + notifyTabs + router.refresh)을 그대로 적용.

#### `useAddDecision()`
```ts
mutationFn: async (input: { title: string }) => {
  // id: crypto.randomUUID() (자동 생성)
  // status: 'pending' (기본값)
  // sort_order: Math.floor(Date.now() / 1000) % 100000 (checklist 패턴)
  // current_value: null, options: []
  const { data, error } = await client
    .from('decisions')
    .insert({ id: crypto.randomUUID(), title, status: 'pending',
              sort_order: Math.floor(Date.now()/1000) % 100000, options: [] })
    .select().single()
}
onSuccess: invalidate(decisions) + notifyTabs(decision-updated) + router.refresh()
onError: toast.error
```

#### `useDeleteDecision()`
```ts
mutationFn: async (id: string) => {
  // soft-delete: deleted_at 갱신 (checklist와 동일)
  await client.from('decisions')
    .update({ deleted_at: new Date().toISOString() }).eq('id', id)
}
onSuccess: invalidate + notifyTabs + router.refresh() + toast.success('삭제되었습니다')
```

### 3. 컴포넌트 — `components/dashboard/decision-tracker.tsx` (수정)

#### 정렬 적용
`sortDecisions(decisions)`로 감싸서 렌더링. 확정 항목이 존재할 때만, 미확정 그룹과 확정 그룹 사이에 얇은 구분선(`border-t`)과 "확정" 라벨을 표시. 미확정 항목만 있거나 확정 항목만 있으면 구분선 없음.

#### 항목 추가 UI
기존 `AddItemButton`(`components/editor/add-item-button.tsx`) 재사용. 추적표 하단에 배치.
```tsx
<AddItemButton
  onAdd={(title) => addDecision.mutate({ title })}
  label="결정 추가"
  placeholder="새 결정 항목 제목..."
/>
```

#### 항목 삭제 UI
각 행에 휴지통 버튼 추가 (checklist-panel.tsx 패턴).
```tsx
<Button size="icon-sm" variant="ghost"
  className="text-muted-foreground hover:text-destructive"
  disabled={deleteDecision.isPending}
  onClick={() => deleteDecision.mutate(d.id)}>
  <Trash2 className="h-3 w-3" />
</Button>
```

#### ID 표시 처리
시드 항목(D1~D7, `/^D\d+$/` 패턴)만 ID 배지 표시. UUID로 생성된 새 항목은 ID 영역 생략하고 제목만 표시.

```tsx
{/^D\d+$/.test(d.id) ? (
  <span className="w-8 shrink-0 font-mono text-xs text-muted-foreground">{d.id}</span>
) : (
  <span className="w-8 shrink-0" />  // 빈 공간 (정렬 유지)
)}
```

### 4. 테스트 — `tests/decisions-sort.test.ts` (신규)

`tests/progress.test.ts` 패턴 따름. `environment: 'node'`, `@` alias 사용.

테스트 케이스:
- 빈 배열 → 빈 배열
- 전부 미확정 → sort_order 순
- 전부 확정 → sort_order 순
- 혼합 → 미확정 상단, 확정 하단, 각 그룹 내 sort_order 순
- 원본 배열 변경하지 않음(불변성)
- 기존 D1~D7 시드 데이터 시나리오 (D1~D3 확정, D4~D7 미확정)

## 데이터 흐름

```
사용자 "+ 결정 추가" 클릭
  → AddItemButton 인라인 입력 토글
  → 제목 입력 + Enter
  → useAddDecision.mutate({ title })
    → INSERT (uuid, title, status='pending', sort_order=timestamp)
    → onSuccess: invalidate + notifyTabs + router.refresh
  → 서버 재조회 → sortDecisions 적용
  → 미확정 영역(pending) 상단에 새 항목 표시

사용자 휴지통 클릭
  → useDeleteDecision.mutate(id)
    → UPDATE deleted_at = now()
    → onSuccess: invalidate + notifyTabs + router.refresh + toast
  → 항목 제거

사용자 status를 '확정'으로 변경
  → useUpdateDecision.mutate({ id, status: 'confirmed' })
    → onSuccess: (이미 구현됨) invalidate + router.refresh
  → sortDecisions 재적용 → 해당 항목이 하단으로 이동
```

## 결정 vs 체크리스트 본질 차이 (유지)

CRUD를 추가해도 두 모델의 본질은 다르다:

| | 결정 추적표 | 체크리스트 |
|---|---|---|
| 질문 | "무엇을 결정했나?" | "무엇을 해야 하나?" |
| 단위 | 의사결정 1개 = 단일값/방향성 | 실행 작업 1개 = 완료/미완료 |
| 범위 | 전역 (팀 간 합의) | 팀 소속 + 마일스톤 연결 |
| 완료 개념 | 상태 4단계 | boolean |
| 개수 | 소수 (게이트) | 다수 (실행 항목) |

결정은 "방향성 합의"를, 체크리스트는 "실행 완료"를 추적한다.
