# 지침 재구성 — 마이그레이션 후속 작업

**상태**: 대기 (마일스톤 UI 대규모 수정 완료 후 진행)
**선행 조건**: 브랜치 `feat/checklist-timeline-integration` 머지 완료
**관련 스펙**: [2026-08-09-지침-재구성-design.md](2026-08-09-지침-재구성-design.md) §10 "명시적 제외"

## 배경

지침 재구성(원칙 카드 방식)에서 결정/마일스톤/체크리스트/이슈 섹션을 제거했다. 하지만 `migrate-from-md.ts`는 마크다운에서 이들을 파싱해 DB를 채우므로, 그대로 재실행하면 DB의 동적 상태 데이터가 소실된다.

마일스톤 UI 대규모 수정 중에는 마이그레이션 파이프라인을 건드리면 충돌 위험이 있어 보류했다.

## 작업 항목

### 1. migrate-from-md.ts 수정

마크다운에서 상태 데이터를 파싱하는 로직을 분리한다:
- `parseGuidelineSections`는 유지 (지침 sections는 새 구조에서도 정상 작동)
- `parseDecisions`/`parseMilestones`/`parseTeamChecklists`/`parseIssues` 파싱 결과가 **빈 배열**이면, 기존 DB 데이터를 보존 (`DELETE` 생략)

핵심 수정 포인트:
- `generateSeed()` 내 `DELETE FROM public.milestones;` / `checklist_items;` / `issues;` 앞에, 파싱 결과가 비었는지 검사하는 가드 추가
- 결정은 `ON CONFLICT DO UPDATE`라 기존 행은 유지되지만, 마크다운에 결정 섹션이 없으면 새 행이 안 들어감 → 기존 데이터 자동 보존 (수정 불필요)

### 2. migrate:md 재실행

```bash
cd sportsday-hub && npm run migrate:md
```

결과 리포트에서:
- `teams: 5` ✅
- `decisions: N` (마크다운에 없으므로 0이어야 함 — 기존 DB 데이터는 보존)
- `milestones: 0` (마크다운에 없음 — DELETE 스킵으로 기존 DB 보존)
- `checklist_items: 0` (마크다운에 없음 — DELETE 스킵으로 기존 DB 보존)
- `issues: 0` (마크다운에 없음 — DELETE 스킵으로 기존 DB 보존)

### 3. 웹앱에서 새 지침 렌더링 확인

각 팀 페이지에서:
- 원칙 카드들이 `## 🎯` 섹션으로 정상 렌더링되는지
- 결정/마일스톤/체크리스트/이슈 탭의 기존 데이터가 유지되는지
- 인라인 편집(Pencil 버튼)이 카드 단위로 작동하는지

### 4. verify-guideline-sync.ts를 package.json에 등록 (선택)

```json
"scripts": {
  "verify:guidelines": "tsx scripts/verify-guideline-sync.ts"
}
```

CI 또는 pre-commit에 추가해 두 소스 불일치를 자동 감지.
