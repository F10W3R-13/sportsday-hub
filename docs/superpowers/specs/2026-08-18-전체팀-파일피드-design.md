# 설계: 전체 팀 파일 피드 (팀 간 파일 공유 가시화 — 1단계)

**날짜**: 2026-08-18
**범위**: 대시보드 '최근 파일 활동' 위젯 + `/files` 전체 목록 페이지 + 페이지 진입 자동 동기화(5분 신선도).
**확정 사항**: 접근법 A(`drive_files` 미러 재사용, 이벤트 로그 없음) · 형태는 대시보드 위젯 + 전체 페이지 · 피드 내용은 드라이브 파일만 · 팀 간 파일 공유 개선의 1단계(2단계: 인계 추적, 별도 스펙).

---

## 1. 배경 / 문제

- 각 팀의 드라이브 파일은 **해당 팀 워크스페이스 개요 탭에서만** 볼 수 있다. 다른 팀이 올린/고친 파일을 확인하려면 팀 페이지를 팀 수만큼 직접 방문해야 한다. (사용자 페인포인트: "다 직접 일일이 봐야 하고 내 팀이 아닌 팀 워크스페이스를 들어가봐야 한다")
- "누가 언제 어떤 파일을" 데이터는 이미 수집된다 — `drive_files` 미러에 `modified_by`(수정자)·`modified_time`(수정시각)·`name`·`team_id`가 저장된다. 없는 것은 이를 **전체 팀 범위로 모아 보는 뷰**뿐이다.
- 2026-08-09 드라이브 연동 설계의 "페이지 진입 시 5분 신선도 확인 후 동기화"가 미구현 상태다(현재 수동 새로고침 버튼만). 신선도 보장이 없으면 "최근 수정" 피드가 오래된 데이터를 최신인 것처럼 보여준다.
- `components/drive/activity-feed.tsx`·`lib/queries/activity-feed.ts`는 구현만 있고 렌더되지 않는 휴면 코드다(8/9 팀 탭 정리 때 제거됨). 이번에 삭제한다.

## 2. 목표 / 비목표

**목표**
- 대시보드에 전체 팀 통합 '최근 파일 활동' 위젯(최근 8건): 팀 배지 · 파일명(드라이브 링크) · 수정자 · 상대시각 · 새 파일 배지.
- `/files` 전체 목록 페이지: 팀 필터(`?team=` URL 연동) + 수동 동기화 버튼.
- 대시보드·`/files` 진입 시 백그라운드 자동 동기화(마지막 동기화 5분 경과 시만) + 완료 후 화면 갱신.
- 마지막 동기화 시각 노출로 데이터 신선도 항상 판단 가능.

**비목표 (안 함)**
- 파일 업로드·수정 — OAuth 스코프 `drive.metadata.readonly` 유지(업로드는 기존대로 로컬 스크립트).
- 파일 이벤트 로그/이력 보존(접근법 B 기각) — 드라이브에서 삭제된 파일은 피드에서도 사라진다(미러 의미론).
- 앱 내 활동(audit_log) 통합 — 파일만. 체크리스트 현황은 기존 위젯이 담당.
- 알림(Slack 등), 인계 추적 — 2단계에서 별도 스펙.
- 서브폴더 재귀 동기화 — 실제 드라이브는 팀 폴더 바로 아래에 파일이 평평하게 위치(확인 완료).
- 페이지네이션·검색 — 파일 수 십여 개 규모가 아니게 되면 그때.

## 3. 아키텍처 — 미러 재사용 + 진입 트리거 동기화

```
[대시보드 · /files 진입(렌더 완료)]
  └─ DriveSyncTrigger(클라이언트) 마운트 1회
       └─ POST /api/drive/sync (비-force, 백그라운드)
            ├─ last_synced < 5분 → 스킵 응답 (변경 없음)
            └─ 경과 → 팀 폴더별 files.list → drive_files upsert
                 └─ 성공 → router.refresh() → RSC 재페치 → 위젯·목록 갱신

[렌더 경로(서버)]
  └─ getRecentDriveFiles(limit): drive_files 전체 팀 modified_time desc
       ├─ RecentFilesWidget  (대시보드, 8건)
       └─ /files 페이지      (상한 100건, 클라이언트 ?team= 필터)
```

- 데이터 소스는 `drive_files` 단일 테이블 — 새 테이블 없음. RLS `drive_files_open_read`(0007) 그대로, `idx_drive_files_modified desc` 인덱스(0007) 활용.
- 동기화 트리거는 항상 **렌더 후 백그라운드** — RSC 렌더를 블로킹하지 않는다(원 설계와 동일 원칙).

## 4. 데이터 계층

**마이그레이션 `0013_drive_files_created_time.sql`**
- `alter table public.drive_files add column if not exists created_time timestamptz;` (nullable — 기존 행은 채워짐: 다음 동기화 upsert 시 값 기입)

**`lib/drive/sync.ts`**
- `files.list` fields에 `createdTime` 추가, `DriveFileMeta`에 `createdTime?: string`, upsert payload에 `created_time` 반영. 그 외 동기화 로직 불변.

**`lib/types/models.ts`**
- `driveFileSchema`에 `created_time: z.string().nullable().optional()` 추가.
- 신규 타입:
  ```ts
  export type RecentFileItem = DriveFile & {
    team: { id: TeamId; name: string; color: string; icon: string }
  }
  ```

**`lib/queries/drive-files.ts` — 신규 쿼리**
- `getRecentDriveFiles(limit = 50): Promise<RecentFileItem[]>`
  - `drive_files` select * · `modified_time desc` · `nullsFirst: false` · limit
  - 팀 목록 조회 후 `team_id` → 팀 메타 매핑은 쿼리 레이어에서 수행(조인은 앱 레이어, 팀 5개라 비용 무시).
  - 팀이 삭제되는 등 매핑 불능 행은 `team`을 `{ id, name: '알 수 없음', color: '#94a3b8', icon: 'FileQuestion' }` 폴백으로 스킵 없이 렌더.
- `getLastSyncedAt(): Promise<string | null>` — 위젯·페이지 헤더의 "마지막 동기화" 표시용(`max(last_synced)`).
- 기존 `getDriveFilesByTeam`(팀 페이지용)은 불변.

## 5. 컴포넌트

**`components/drive/recent-files-widget.tsx` (서버 컴포넌트)**
- `app/page.tsx` 기존 `Promise.all`에 `getRecentDriveFiles(8)`·`getLastSyncedAt()` 추가.
- 행 구성: 파일 아이콘(기존 `DriveFileIcon` mime 분류 재사용 — FileList와 동일 방식) · 파일명(`web_view_link` 새 탭, 없으면 텍스트) · 팀 배지(팀 색상) · `modified_by`(없으면 '—') · `timeAgo(modified_time)`.
- **새 파일 배지**: `created_time`이 now-72h 이내 → `NEW` 라벨. 그 외는 수정 아이콘(FilePen). 배지 판정은 순수함수 `isNewFile(createdTime, now)`로 분리(테스트 대상).
- 헤더: "최근 파일 활동" + `전체 보기 →`(`/files` Link) + 우측 소자로 `마지막 동기화 {timeAgo}`.
- 배치: UrgentChecklist와 TeamStatusCard 사이.
- 상태: 파일 0건 → "동기화된 파일이 없습니다" 안내. 드라이브 미연결 → "구글 드라이브 연결 필요" + `/settings` 링크(연결 상태는 기존 `getDriveConnectionStatus` 재사용).

**`app/files/page.tsx` + `components/drive/file-feed-client.tsx`**
- 서버: `getRecentDriveFiles(100)`·`getLastSyncedAt()` → 클라이언트 컴포넌트에 전달.
- 필터 칩: 전체 + 5팀. 선택은 URL `?team={teamId}`가 진실 원천(기존 `?tab=` 패턴 동일). `useSearchParams` + Suspense 래퍼 구조는 `team-tabs.tsx` 방식 준용. 유효하지 않은 값은 '전체' 폴백.
- 행: 위젯 행 + 생성일 소자. 수동 "동기화" 버튼 — 기존 FileList의 sync 뮤테이션(`POST /api/drive/sync` force) 재사용, 완료 후 `router.refresh()` + 토스트.

**`components/drive/drive-sync-trigger.tsx` (클라이언트, 신규)**
- 마운트 시 1회 `POST /api/drive/sync`(비-force) → 응답이 "실제 동기화 수행됨"인 경우만 `router.refresh()`. 스킵·실패는 무연산(실패 UI 없음 — 신선도 표시가 이미 상태를 설명).
- RecentFilesWidget 하단(대시보드)과 `/files` 페이지에 장착. useEffect 의존 `[]`, StrictMode 이중 마운트는 API 스킵 로직이 흡수.

**휴면 코드 정리**
- `components/drive/activity-feed.tsx`·`lib/queries/activity-feed.ts`·`ActivityFeedItem` 타입·`lib/queries/keys.ts`의 `activityFeed` 키·관련 테스트 삭제.
- `components/team/team-tabs.tsx`의 잔여 prop `activityFeed?: never`도 함께 삭제.
- `timeAgo`가 `file-list.tsx`·`activity-feed.tsx`에 중복 존재 → `lib/format/time-ago.ts`로 추출, `file-list.tsx`는 import로 교체.

## 6. 동기화 신선도 정책

- `POST /api/drive/sync` 비-force 스킵 임계를 **60초 → 5분**으로 변경(2026-08-09 설계 148행의 원안 구현).
- 수동 버튼은 기존처럼 `force: true`로 즉시 실행.
- 여러 탭 동시 진입 시 경합: `last_synced` 선확인이 가드 역할. 뚫고 동시 실행돼도 upsert가 멱등(`onConflict: file_id`)해 무해.
- Drive API 실패·토큰 만료: 기존 `syncDriveFiles` 오류 경로 그대로(실패 응답 → 트리거 무연산).

## 7. 오류 처리

| 상황 | 동작 |
|---|---|
| 드라이브 미연결 | 위젯·페이지에 "구글 드라이브 연결 필요" + `/settings` 링크 |
| 동기화 실패(API 오류) | 직전 미러 데이터 렌더 유지 + "마지막 동기화 X분 전"으로 신선도 노출 |
| `drive_files` 0건 | 빈 상태 안내(미연결이면 설정 링크로 전환) |
| `modified_time` null | 정렬 맨 뒤, 시각 `—` |
| 팀 메타 매핑 불능 | 회색 폴백 배지('알 수 없음') |

## 8. 테스트 (vitest, 기존 패턴 준용)

- `getRecentDriveFiles`·`getLastSyncedAt`: supabase mock — 정렬·limit·팀 매핑·폴백 배지.
- 신선도 판정: 5분 경계(4:59 스킵 / 5:01 실행) — sync 임계 로직이 별도 함수면 직접, 아니면 라우트 핸들러 간접.
- `isNewFile`: 72h 경계(71:59 true / 72:01 false)·null/undefined false.
- 팀 필터 파싱: 유효 id·무효값 폴백·전체.
- `timeAgo` 추출 후 기존 분기(분/시간/일/날짜) 테스트 이동·유지.
- 휴면 코드 삭제에 따른 관련 테스트 제거 — 커버리지 총량 유지 확인.

## 9. 2단계(인계 추적) 확장 고려 — 이번엔 구현 안 함

- `handoffs` 테이블(주는 팀·받는 팀·무엇·기한·상태·체크리스트 항목 링크)은 별도 스펙으로 설계.
- 인계 뷰에서 "해당 팀 최근 파일"을 붙일 수 있도록 피드 조회·필터를 재사용 가능한 형태(순수함수 분리)로 유지하는 것만 이번 설계가 책임진다.

## 10. 결정 기록

- 위젯 표시 건수 **8건**(구 ActivityFeed limit 관례 승계), 새 파일 배지 기준 **72시간**, 위젯 배치 **UrgentChecklist와 TeamStatusCard 사이** — 2026-08-18 사용자 승인.
- 접근법 B(이벤트 로그)는 5팀·수십 파일 규모에서 과설계로 기각. A로 부족해지면 그때 재검토.
- 옵션 1(체크리스트 인계 필드)·옵션 3(텍스트 파싱)은 2단계 브레인스토밍에서 기각 예정 후보로 기록.
